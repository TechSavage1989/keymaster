# Keymaster

A browser app that cuts 3D-printable sculptures and figures into pieces and adds alignment keys (pegs, dowel holes, magnet pockets) so the pieces line up when glued. Users are artists and hobbyists, not engineers. The bar is "feels like a polished tool," not "technically works."

## Layout

- `src/core.js`: geometry engine. Pure JavaScript, **no dependencies, no DOM, no three.js**. Parsing, welding, plane sections, capping, keys, connected components, STL and ZIP writing.
- `src/app.js`: the interface. three.js r147 (UMD builds from jsDelivr), viewport, cut gizmo, live preview, parts list, inspector, undo, export.
- `src/template.html`: markup and all CSS.
- `tools/build.py`: inlines `core.js` and `app.js` into `template.html` to produce `index.html` (the shipped single file) and `tests/test.html`.
- `tests/core.test.js`: geometry tests (Node). `tests/ui_test.py`: interface tests (Playwright, using `tests/mock-three.js` as a three.js stand-in).
- `tools/sculpt_check.js`: sweeps hundreds of cuts through real model files and reports any part that isn't sealed (repairing an open model first, as the app's Repair surface would).

## Commands

```
node tests/core.test.js        # geometry
python3 tools/build.py         # rebuild index.html after any change in src/
python3 tests/ui_test.py       # interface (needs: pip install playwright && python -m playwright install chromium)
```

Always rebuild and commit `index.html` with any `src/` change. CI fails if it is stale.

## Rules that must not break

1. **Every exported part is a closed, correctly oriented solid.** Any change to cutting, capping, keys or repair needs a test in `core.test.js` that checks `edgeReport(...).closed` and positive volume, plus a volume-conservation check where it applies.
2. **Units are millimeters** everywhere. Clearances are per side.
3. **`core.js` stays dependency-free** so it can move into a Web Worker unchanged.
4. **Models never leave the browser.** No uploads, analytics, or network calls besides the pinned script and font CDNs.
5. The published page has a strict content policy: scripts only from cdnjs, `cdn.jsdelivr.net/npm`, `cdn.tailwindcss.com` and `code.jquery.com`, pinned to exact versions at least two weeks old. No other network requests.
6. File saving goes through the `downloads` capability when present (ZIP only; STL alone is not an allowed extension there), with a plain link fallback.

## How the cut works (read before touching `cutMesh`)

The plane is a frame `{o, n, u, v}` with `u × v = n`. Key positions are 2D `(x, y)` in that frame, which is the same as the cut plane object's local space in the app. `computeSection` nudges the plane by a tiny amount if any vertex sits on it, chains crossing segments into loops, and `buildRegions` nests loops into areas (outer plus holes). Each side gets its own copy of the section vertices; caps are triangulated with the built-in earcut and then `fixTJunctions` re-inserts any ring points earcut dropped, so cap edges always match the side walls. Skipped areas leave their crossing triangles whole, which is how "leave this area joined" works. Shells the cut never touched (eyes, inner voids) are merged into the piece that contains them.

**Real sculpts are messy, so the cap has several safety layers** (each found on real figure files, each with a test):
- `prepareMesh` drops loose specks (`removeSpecks`: shells under 0.001 mm³ and 0.5 mm, such as a triangle stored back to back with itself).
- `buildSection` moves the plane, by a few microns at most, to the middle of the widest gap among nearby vertices, so no section points crowd together beyond float32 precision.
- `buildRegions` nests by direction, not just depth. An opposite-running loop inside an outline is a hole. A same-running one is an overlapping inner solid (`nested`: its own cap, an obstacle for keys, never keyed). A lone backwards loop is a void speck (`inverted`: capped facing the other way, never shown or keyed).
- `untangledRing` snips microscopic self-crossing folds out of the outline before earcut. Microscopic holes skip earcut entirely.
- `fixTJunctions`, `splitThroughPoints` and `patchCap` then make the cap meet every ring edge exactly. `patchCap` orients by topology, because the leftovers are often zero-width slivers.
- `cutMesh` checks that every part is closed and, if not, retries a hundredth of a millimetre or so either side (`cutOnce`). If every retry fails it throws a plain-language error rather than export an open part.

Before merging any change to sectioning, capping or keys, run `node tools/sculpt_check.js <model files>` on real sculpts as well as the tests (`MIN_WALL=1.2 CURVED=1` adds the printability rules and curved cuts along every region line). Never commit model files; they are usually someone else's work. `tests/fixtures/sculpt-outlines.json` holds just a few 2D cut outlines that once failed.

Key outlines come from `keyProfile(shape, r, d, angle, res)`. A socket is the peg outline grown by the clearance `d` (never scaled), and the vertex count depends only on `shape` and `res`, so tapered top and bottom rings pair up. **Every key shape must be star-shaped around its centre**: the cap fans and the wall orientation in `cutMesh` and `makePin` rely on it, and `core.test.js` checks it. Peg taper is a percentage (`cfg.taper`, 0 to 100, where the old `true` means 20); the tip never shrinks below 2% of the width so it stays a real outline. A matching socket grows by `spec.cs = c·√(1+slope²)` so the gap holds at right angles to the sloping wall. Use `spec.cs`, not `spec.c`, for anything socket-sized. Each key may carry its own settings in `key.o` (any of `KEY_OVERRIDES`: shape, diameter, length, clearance, taper, taperSocket, turn, align); the key type and peg side stay global. Merge them with `keyCfg(cfg, key)` and size anything for that key from `keyGeometrySpec(keyCfg(...))`. `evaluateKeys` checks a custom key at its own depths via `depthFor`, which sections them once and caches them on the analysis. Keep `key.o` when moving or flipping keys. By default keys are sized to fit each area (`cfg.sizeMode: 'auto'`): `autoFitKeys` tries `sizeLadder(cfg)` from the Largest setting down to the Smallest (pegs 1.2× as long as wide, dowel pins 2.5×, magnets from standard disc sizes), keeps each key to at most half the area's width so walls stay sturdy, and stores the chosen size in `key.a`, which `keyCfg` applies under `key.o`. `PRINTERS` holds the resin and filament presets (smallest key, gap, wall) that the model panel's Printer choice applies. The Largest key (`cfg.diameter`, the top of the ladder) follows the model's size (`fitKeySizeToModel`: 3.5% of the longest side, 5 to 15 mm, as kits of that size use) when a model is opened or scaled, until it is set by hand (`cfg.sizeByHand`): on a figure scaled to 300 mm a 5 mm peg was a dot. `KEY_SIZES` goes up to 15. `autoPlaceKeys` searches a grid, then, for any area where nothing fit, searches finer around its nearest misses (ranked by `slack`, how far a spot is from passing the check that stopped it), because thick walls or long shapes can leave a valid strip narrower than the grid. It returns the areas still without a key in `keys.empty`, with the reason, and the interface names them. Fit checks for non-round shapes use `footprintClear`, which follows the real outline. `splitThroughPoints` repairs cap edges that earcut runs straight past ring points, which happens when straight socket sides line up.

## Plugs

The fifth joint type (`cfg.type: 'plug'`), from the owner's own technique and professional kits: the cut face itself, pulled in from the edge by the wall, stands out from one piece into a matching pocket in the other, one per area. `planPlugs(an, cfg, skip)` works on flat (`analyzePlane`) and curved (`analyzeLoop`) analyses alike and returns, per listed area, `{ ok, reason, x, y, base, top, mouth, floor, depth, side }`: four anticlockwise rings with the same number of points (the plug's base and top, the pocket's mouth and floor) and the pocket's side (as for pegs, from `pegSide`).
- **Shape** (`plugShape`): the area rasterised on a fine grid, its distance from the edge (`distanceField`, an exact Felzenszwalb transform), kept where it's at least `inset` in, then rounded (the core grown back by `round`, at least the wall and 1 mm) so narrow necks and sharp corners drop out, the biggest piece traced (`contourLoops`, marching squares) and evened out (`evenRing`). Areas with a hole through them get no plug.
- **Rings**: the top is the base moved in by depth × tan(`plugSlope`, 5° by default) and the pocket is the plug grown by the gap held square to the slope, both by `offsetRing`; every ring is checked for crossings. A crossing outline is rounded twice as much first, and where the top ring folds over at a concave corner the plug is made shallower (×0.7 a step, down to 1 mm) before it is refused as irregular: a goblin's shoulder at 12° was refused outright for this.
- **Depth**: as deep as fits up to half the plug's narrower width (2 to 10 mm), or `plugDepth` when `plugDepthMode` is `set`, always capped by what the other piece can hold (checked along lines through the model: solid past the pocket's floor plus a floor, and round its walls). On rounded parts the other piece thins near the edge, so `planPlugs` also tries the plug pulled further in (1.5 to 6 walls) and keeps the deepest, up to the depth wanted.
- **Building**: `cutMesh(..., { plugs })` and `cutAlongLoop(..., { plugs })`. On flat cuts the plug's piece gets a hole at the base ring, the pocket's piece one at the mouth, each with walls facing along their own edges and a flat end from `endCap`, so any outline works. `endCap` orients the whole end at once from the outline's direction, never triangle by triangle: earcut leaves slivers where points line up, and far from the origin on a tilted cut a sliver's own normal can point the wrong way (the tree-trunk outline in `plugOutlines` caught this). On curved cuts `curvedLoopCap` treats keys and plugs alike as four outlines on the face that follows the line. Plugs set the pull direction like keys. **On curved cuts, "Pegs on" / "Plug on" means the piece being split off ("This piece") or "Other piece"**, not the halves of a flat cut: the app maps the choice per line through `curvedSide(pref, into2)` (side 1's material lies at -into2·n; 'below' names side 1) and passes `pegSide` per loop in `opts.perLoop[i]`, which `cutAlongLoops` folds into each line's `c.cfg`. Before this a plug on a shoulder stood on the body with its pocket in the arm, which read as "the other piece is too thin".

## Repair

`repairMesh(P, I)` makes a tangled export cuttable and reports what it did, in up to three passes (filling a hole can expose the next flaw): `{ duplicates, untangled, pinched, flipped, slivers, filled, skipped, report }`. Each pass: faces stored twice go (a face and its mirror twin are a zero-thickness fin, so both go); an edge with three or more faces, or two running the same way, has its faces paired by which side their material lies on (sweeping round the edge, a face's material is behind its normal) and its vertices split so each pair is its own surface (two parts welded along a seam become two shells); every vertex whose faces form more than one fan is split too (a pinch, which the hole filler can't close); each connected surface is walked so faces agree with their neighbours, and a closed one facing in is turned out; open slivers under 0.5 mm go; then `fillHoles`. `edgeTable` groups half-edges by their smaller vertex in typed arrays, so the faces on an edge are a short scan; the whole repair of a 400k-triangle part takes a few seconds. Stitching coincident boundary vertices was tried and dropped: it rejoined what untangling had separated. Models it can't close (the guenve pair: 1,000 open edges, 16 shells) are a job for Blender or Meshmixer, and the app says so with the count. In the app, **Repair surface** in the model panel runs it on every part.

## Cuts that print and go together

The owner's two rules: no cut may leave a piece too thin to print, and no cut may make pieces that can't be put together. Both are enforced in `core.js`, so the app, tests and `sculpt_check` all obey them.
- **Too thin.** `thinAreas(an, t)` casts lines along the plane's normal through each area (`rayGrid` and `solidRuns`, cached while the plane only slides; crossings count in or out by which way the surface faces, so overlapping shells such as eyes don't read as gaps) and measures the piece on each side. An area is too thin on a side when every sample is thinner than `t`, or when the thin samples at least `t` in from the outline cover 40% of the area (the thin band along a slanted cut's edge is normal and ignored). `cutMesh(..., { minThickness })` refuses listed areas with `thinMessage` (code `thin`) and quietly leaves thin unlisted specks joined. The app passes `minWall()`: the Wall setting, capped at the printer's wall. It shows the warning in the footer with **Leave it joined**, tags the area "too thin", and holds back Cut. Curved cuts check the two pieces where they meet with `jointThickness`.
- **Cut anyway.** The owner asked to be able to force cuts. `opts.force` on `cutMesh`, `cutAlongLoop(s)` and `splitRegion` turns the `thin` and `locked` refusals into `result.warnings` (`[{ code, message }]`); listed thin areas are then cut, only unlisted specks stay joined; `crack` and unsealed results still throw. In the app, a thin or hooked refusal on a region pick re-runs the pick with `force` and offers **Split it off anyway** / **Cut along it anyway** under the warning; the flat cut's footer and the held-back toast offer **Cut anyway** (`doCut(true)`), and a locked refusal's toast does too. A forced cut says so in its toast.
- **Only a crack.** If joined areas hold both faces of a cut area in one piece, `cutOnce` throws (code `crack`).
- **Hooked or caged.** `lockedPairs` / `slidesApart` compare the pieces column by column along the pull direction: each pair must be able to slide `pullDistance` apart (past the longest key, at least 3 mm) straight along the keys, or, with no keys, at a slant up to 40° or from one piece's middle to the other's. Clashes shallower than 0.05 mm or narrower than three columns are slivers and are ignored, and pieces that already overlap (an inner solid) print as one. On flat cuts only pairs that can lock are checked: one reaches across the cut through a joined area, or both are on the same side (a piece caged inside another). Code `locked`.
- **Lines cut together agree** (`orientLoops`): side 1 holds every line's forward edges, side 2 the rest, worked out from the pieces of surface the lines bound; `loopFrame` gives the same frame whichever way a line runs, so keys planned before a line is turned round stay where they were. The app orients hand-picked lines before planning keys.
- **Curved cut faces.** `straightLoop` moves a line off two sides of a triangle onto the third, so zig-zags along mesh edges don't fold the cap into teeth; `analyzeLoop` and `cutAlongLoop` both use it, so keys and cut agree. The cap is flat (earcut) unless it would repeat a surface edge, the line crosses itself flattened, or it doesn't seal; then it is fanned from `fanCentre`, a point the line can be seen from all round when there is one.
- **Smooth cut faces.** A cap drawn only between the line's own points is a few big facets, so a bumpy line gives a faceted face (the owner's complaint on a neck cut). `gridCap(rings, xyOf, H, step, addVertex, xyMap, wantCCW)` draws it as a regular grid instead: grid points at least three-quarters of a `step` in from every ring (the line and any key or plug outlines) get the face's height from `capHeight`, the cells with all four corners in are two triangles each, the grid's outline is traced into loops, and the band between each ring and the grid is earcut with the flat-cut safeguards (`fixTJunctions`, `splitThroughPoints`, `patchCap`). `capStep` is 1.5× the line's median edge, never finer than about 4,000 cells. It returns null for shapes too small or awkward for a grid, and the caller falls back to the plain cap (flat, or fanned where the flat cap clashed). The grid is tried even where the flat cap would be fanned, since its band often avoids the surface edge the flat cap doubled. The clash check (`surf`) covers the surface edges on both sides of the line, with side 2's copies mapped back to their original ids: a cap chord that doubled an edge on side 2 alone once slipped through and made a part with a four-face edge. `cutAlongLoops` retries without grids, then with fans, if a part isn't sealed. Both pieces share the grid points exactly (`addVertex` makes a pair, `copy`/`other` link them). Midpoint subdivision of the earcut triangles was tried first and dropped: skinny earcut triangles stay skinny when split, so the face still crinkled, and it added ten times the triangles. Keep an eye on the cost: on a 140k-triangle miniature, splitting off a region adds a few thousand triangles and takes about a second.

## Sunk cut faces

The owner's "impossibly thin walls": a shallow region split off along its outline is a lens that thins to nothing at the rim, because the cap membrane hugs the surface there. Smoothing the region labels (morphological opening, tried at 0.8 to 2 mm) did not help and was dropped; what helps is **sinking the face**. `sunkRing(P, I, F, ring, xy, h, into2, want, wall)` pushes each line point straight along the frame normal into side 2 (`intoSide2`: the piece that doesn't hold the line's forward edges; for lines picked by hand `orientLoops` makes side 1 the smaller side, so the recess goes into the bigger piece) as far as there is solid to hold it with a wall to spare, checked with `solidRuns` (nothing where only air lies beyond the line, as under an overhang or along a ball's widest part), smooths the depths along the line (moving minimum, then mean, over a wall's length) and checks the face over the sunk ring the same way (10th percentile of room at least three-quarters of a wall, halving the depth otherwise). Walls that followed the other piece's surface normal were tried and dropped: on a bumpy line the pushed points crossed each other. `cutAlongLoops` with `opts.sink` builds, per loop, a sunk ring of new vertices, straight walls from the line down to it (quads `(b, a, la), (b, la, lb)` on side 1, mirrored on side 2), and the cap (grid or keyed, `curvedLoopCap(..., sunk)`) over the sunk ring; `analyzeLoop` with `cfg.sink` uses the sunk ring as the base loop, so keys, plugs and checks all sit on the sunk face. Recesses at both ends of a piece trap it (a sleeve sunk into the shoulder and the cuff), so when the lock check fails the longest line alone is sunk, then none, before the refusal stands (`sinkPlans`, `c.use('sunk' | 'plain')`). The result carries `sinks` per loop. In the app, **Sink face** (mm, 0 off, default 1) sits in the regions panel beside **Draw a cut line**; the pick says how deep the face is sunk, or that there's no room.

## Painted selections

What Meshmixer and ZBrush do, and what the owner asked for ("similar ability to make cuts as in meshmixer, or zbrush"): paint faces with a brush, split them off, cap the holes. `brushTriangles(P, I, start, centre, radius)` floods from the triangle under the brush across the surface (`triangleAdjacency`, cached per index array, with centroids) keeping triangles within the radius, so a dab on a hand doesn't paint its far side; `growSelection` / `shrinkSelection` work in millimetres (Dijkstra from the selection's edge over centroid distances; shrink grows the complement); `tidySelection` opens then closes by `r`, dropping tongues and filling notches narrower than 2r. `selectionSeg` turns the selection into a two-group labelling (1 painted) through `bordersFromGroups`, and `splitRegions(P, I, seg, [1], opts)` cuts it like a region: a painted area always has a closed outline, so it always separates (unlike a single clicked line), and keys, plugs, sinking, force and shift-click apply. In the app, **Paint an area** in the regions panel (`setPainting`) makes drags on the chosen part paint (`paintAt` raycasts the part's mesh for the point and `faceIndex`; `paintDab`), Shift-drag or the **Erase** toggle erase, the brush size is in mm, **Grow**, **Shrink**, **Tidy edge** and **Clear** edit the selection (`paintEdit`), and letting go of the pointer picks the painted area (`pickPainted`, `state.regions.last.painted` for replays). Painted triangles show blue over the region colours (`renderPaint`, from `v.regionColors` kept by `applyRegions`). Drawn-line dots are fixed-size `THREE.Points` now, after the owner found the spheres obstructed the view. The brush shows as a circle its own size lying on the face under the pointer (`brushRing`, `moveBrushRing`, `hoverBrush`); it starts at 3% of the part's diagonal until set by hand (`state.paint.sized`), because a 3 mm brush on a figure scaled to 254 mm painted nothing visible; the selection resets if the part under the brush changes (scaled, or another chosen); and **Show faces** (flat shading, `state.flat`, `setFlat`, the view-tools button `#flatBtn`) is on by default (the owner's request) and turned on by painting if off. **Painting never waits on a cut**: a dab writes only the faces it touched and sends only their span to the graphics card (`renderPaint(only)` with `updateRange`), raycasts are throttled to one per 20 ms, and letting go shows the outline alone (`previewPainted`: `selectionSeg` + `groupLoops`, tens of milliseconds, `pick.preview`); **Split off painted area** (`splitPainted`) then runs the full pick with keys, plug, sinking and checks and cuts at once if it passes, or shows the refusal with **Split it off anyway**. Before this every stroke end ran the whole cut (a second or more) and every mouse move rewrote and re-uploaded all the model's colours.

## Lines drawn by hand

The owner's "manual painting capability for cuts". `drawnLoop(P, I, points)` takes clicked points (part coordinates), snaps each to its nearest vertex (`nearestVertex`) and joins them in order, and back to the first, by `surfacePath`: Dijkstra over the vertex graph (`vertexAdjacency`, cached per index array) with edges charged a little extra for straying from the straight line between the two points, so the way runs where a hand would draw it. Where a vertex comes round again the detour is dropped, so the loop is simple. The result is a loop like `borderLoops` gives (`verts`, `closed`, `length`, `drawn: true`), so `cutAlongLoop`, `analyzeLoop`, keys, plugs, force and shift-click all work on it unchanged. In the app, **Draw a cut line** in the regions panel (`setDrawing`) turns clicks on the chosen part into points (`addDrawPoint`, dots and the path so far in blue from `renderDraw`); Enter, the **Close the line** button or a click by the first point closes it (`closeDrawing`) and picks it like any line; Backspace takes a point back, Esc stops drawing. The drawn loops are kept in `state.regions.last.drawn` (an array: drawing again adds a line to the lines already picked, so several drawn lines cut together; Esc clears the pick for a fresh start) so the pick replays when the key settings change. Curved key markers draw through the model (`depthTest: false`), as the plug marker did, so pegs inside a limb can be seen.

## Cut suggestions

`neckSweep` slices the part along `sweepDirections` (13 fixed plus the principal axes), follows each area from slice to slice, and flags a cross-section that pinches below 60% of the wider ones on both sides. `refineNecks` merges these, tilts each plane until it sits square across the neck, and keeps one spot per even neck. `creaseEdges` and `creasePlanes` find planes where inward creases cover at least a quarter of the cut outline. `separateShells` finds solids that don't touch (inner shells stay with their host). The app runs the search a direction at a time between frames, caches results per part, and letters the suggestions (areas are numbered). A narrow-point suggestion sets `state.cut.focus`, and the next analysis leaves every other area joined.

## Surface regions

`segmentSurface` joins neighbouring triangles whose normals differ by less than `angle`, like ZBrush polygroups by normals, then melts regions under `minFrac` of the area (0.3%) into the neighbour they share the longest border with. With `fold` set (the app uses `fold: 15, angle: 60`), a concave turn (a valley: cloth meeting skin, a collar, a belt's edge, a shoe top) splits at that gentler angle while a convex one (a ridge) still needs `angle`: on organic sculpts the parts meet in valleys and ridges are mostly detail, so this gives arms, legs, hands, heads and garments as their own regions where splitting at any turn merged them. It returns `groupOf` per triangle, region areas, and `borders` (pairs of triangles and their shared edge). `regionBorderLines` turns the borders into line segments lifted a hair off the surface. In the app, the view-tools button colours every part by region (`applyRegions`), with the fold slider in a small panel; the cut preview steps aside while regions show, and cutting turns them off.

## Curved cuts along a border

**Splitting off a region** is what ZBrush and Meshmixer do with a selected group, and the owner's expectation. `splitRegion(P, I, seg, g, opts)` cuts along the region's whole outline, all its loops at once (`regionLoops`; an arm has a shoulder loop and a cuff loop), through `cutAlongLoops(P, I, loops, opts)`: side 1 is the triangles holding the loops' own directed edges (the region, since `regionOutlines` runs with the region's winding), flooded with every loop's edges blocked; side 2 is the rest, split into pieces with `separateShells`. Loops are cut together, never one at a time, because where the surface loops back on itself (an arm whose hand rests on the hip) no single loop separates it. Keys or a plug go on each loop from `opts.perLoop[i]`; the thickness and lock checks run per loop on the two pieces it separates, and a region held at more than one end by one piece (a shin between a thigh and a shoe standing on the same base) is refused with a message to split a neighbour first. `cutAlongLoop` is a one-loop wrapper. In the app, a click within 1.5% of the part's size from a border line cuts along that line; a click anywhere else on the part picks the region under it (`regionAtPoint`) and offers **Split off this region**. **Shift-click adds to the pick**: more lines (cut along them all at once through `cutAlongLoops`, which then separates both sides into their shells; `opts.what: 'lines'` words the "doesn't free a piece" message) or more regions (`splitRegions` / `groupLoops`: the union's outline, with the borders between the chosen regions dropped, so a face, hair and collar come off as one head; regions that don't touch come off as separate pieces). Lines add to lines and regions to regions; shift-clicking something already picked takes it out again. The clicks are kept in `state.regions.last.clicks` and replayed (`replayPick`) when the key settings change.

`cutLines` lists the lines a curved cut can follow: borders between two regions (`borderLoops`) and whole region outlines (`regionOutlines`), which can run past several neighbours. `borderLoopNear` picks the shortest closed line through the border edge nearest a clicked point. `cutAlongLoop` splits the surface along that line's existing edges: it floods the triangles on each side (refusing a line that doesn't split the part), gives side 2 its own copy of the line's vertices, and caps both sides with the same triangulation facing opposite ways. The cap is the line projected on its best-fit (Newell) plane and triangulated with the flat-cut safeguards; if any cap edge would repeat a surface edge (a border zig-zagging along triangle edges) or the line folds over when flattened, it fans from a centre point instead. A line round a dip gives a piece of negative volume and is refused with its own message. Untouched shells join the piece around them. **Hollowed models are a known gap**: a curved cut only cuts the outer surface, so an inner void shell that the cap passes through stays whole and is merged into one piece, which then reads as a dip (negative volume) or hides a void that spans both pieces. Flat cuts slice inner shells like any other. Keys on a curved cut sit on a face that follows the line however much it bends (`curvedLoopCap`): the face's height off the best-fit plane is blended from the line's heights by mean value coordinates (`capHeight`, and `capHeightGrid` for fast lookups), triangulated once with a hole per key's socket outline and shared by both pieces so they meet exactly. The peg's piece adds a thin ring of face across the fit gap, then the peg. Keys are straight, along the plane's normal: a peg's length counts from the highest point of its base on the socket's side, so it always reaches its full length into the other piece, and each socket is measured the same way from its own side (`keyLevels`). `analyzeLoop` gives an analysis shaped like `analyzePlane`'s, so `autoFitKeys`, `autoPlaceKeys` and `evaluateKeys` work unchanged on it; `keyScore` sends curved analyses to `curvedKeyCheck`, which checks along lines through the model (`solidRuns`): no more than 45° of slope under the key, solid walls to the socket floor, a solid floor, and, for pegs, solid at least a wall's depth under the peg in its own piece, so it's anchored. A line that crosses itself when flattened (beyond microscopic folds, which are snipped as on flat cuts) is cut without keys. While surface regions show, the hidden cut plane ignores the pointer: drags orbit. A click on a part that isn't the selected one selects it (`regionClick`), so its key settings show on the right; a click on the selected part picks a region or line on it. Turning regions on with a single part selects it. A change to the key settings re-runs the last pick (`state.regions.last`), so the pegs or plug on the picked region follow the settings.

## Interface conventions

- Copy: sentence case, plain verbs, say what a button does ("Cut part", "Export parts"). Errors say what happened and how to fix it, without apologizing.
- Yellow (`--cut`, `#F2B705`) means cutting: the hatched section face and the cut button. Do not use it for anything else.
- Font: Barlow with tabular numbers. Colors come from CSS variables with light and dark values.
- Each part gets a muted filament-like color from `PALETTE`. Pins are grey.
- Keyboard: Enter cut, Esc done, X/Y/Z align, F frame, Delete remove key, Ctrl+Z / Ctrl+Shift+Z.
- Cut plane controls, all available at once with no modes (the owner's request): the TransformControls arrow slides it, the two rings tilt it (Shift snaps to 5°), and a drag anywhere on the plane tips it like the edge of a tray (Shift for fine control). A plain click on the cut face still adds a key, because a plane drag only starts after the pointer moves 4 px. Dragging off the plane orbits, and Alt-drag orbits from anywhere. The X/Y/Z angles are turns about the world axes applied X, then Y, then Z, starting from a level cut (`planeAngles` / `setPlaneAngles`).
- **The exploded view moves pieces along their cuts**: each piece made by a cut carries `pull`, a unit direction away from the piece across the cut (flat cuts: ±the plane normal by side; curved cuts: the sum of ±each line's frame normal, set in `checkPieces`), and `applyExplode` moves it that way by up to a quarter of the model's diagonal; a piece without one (the original) moves out from the middle as before.
- **Scale and orientation stay on screen**: the `#modelTools` chip at the top left of the view (Turn X/Y/Z, × 0.1, × 10, a percentage) works whatever is selected (the owner's request); the model panel keeps the fuller controls.
- **Every setting must be visible without scrolling** on screens from 1280×800 up (the owner's request; `ui_test.py` checks 1280×800, 1366×768, 1440×900 and 1920×1080). The cut plane controls and the area chips live in the toolbar along the bottom of the view (`planeBarHTML`), suggested cuts in the left panel, and key settings in the right panel, with labels beside their boxes. Key status and warnings sit in the pinned footer above **Cut part**, so they show however the panel is scrolled. When adding a setting, make room for it; don't let the panel grow past the screen.
