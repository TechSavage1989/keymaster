# Keymaster

A browser app that cuts 3D-printable sculptures and figures into pieces and adds alignment keys (pegs, dowel holes, magnet pockets) so the pieces line up when glued. Users are artists and hobbyists, not engineers. The bar is "feels like a polished tool," not "technically works."

## Layout

- `src/core.js`: geometry engine. Pure JavaScript, **no dependencies, no DOM, no three.js**. Parsing, welding, plane sections, capping, keys, connected components, STL and ZIP writing.
- `src/app.js`: the interface. three.js r147 (UMD builds from jsDelivr), viewport, cut gizmo, live preview, parts list, inspector, undo, export.
- `src/template.html`: markup and all CSS.
- `tools/build.py`: inlines `core.js` and `app.js` into `template.html` to produce `index.html` (the shipped single file) and `tests/test.html`.
- `tests/core.test.js`: geometry tests (Node). `tests/ui_test.py`: interface tests (Playwright, using `tests/mock-three.js` as a three.js stand-in).
- `tools/sculpt_check.js`: sweeps hundreds of cuts through real model files and reports any part that isn't sealed (repairing an open model first, as the app's Repair surface would).

## Commands

```
node tests/core.test.js        # geometry
python3 tools/build.py         # rebuild index.html after any change in src/
python3 tests/ui_test.py       # interface (needs: pip install playwright && python -m playwright install chromium)
```

Always rebuild and commit `index.html` with any `src/` change. CI fails if it is stale.

## Rules that must not break

1. **Every exported part is a closed, correctly oriented solid.** Any change to cutting, capping, keys or repair needs a test in `core.test.js` that checks `edgeReport(...).closed` and positive volume, plus a volume-conservation check where it applies.
2. **Units are millimeters** everywhere. Clearances are per side.
3. **`core.js` stays dependency-free** so it can move into a Web Worker unchanged.
4. **Models never leave the browser.** No uploads, analytics, or network calls besides the pinned script and font CDNs.
5. The published page has a strict content policy: scripts only from cdnjs, `cdn.jsdelivr.net/npm`, `cdn.tailwindcss.com` and `code.jquery.com`, pinned to exact versions at least two weeks old. No other network requests.
6. File saving goes through the `downloads` capability when present (ZIP only; STL alone is not an allowed extension there), with a plain link fallback.

## How the cut works (read before touching `cutMesh`)

The plane is a frame `{o, n, u, v}` with `u × v = n`. Key positions are 2D `(x, y)` in that frame, which is the same as the cut plane object's local space in the app. `computeSection` nudges the plane by a tiny amount if any vertex sits on it, chains crossing segments into loops, and `buildRegions` nests loops into areas (outer plus holes). Each side gets its own copy of the section vertices; caps are triangulated with the built-in earcut and then `fixTJunctions` re-inserts any ring points earcut dropped, so cap edges always match the side walls. Skipped areas leave their crossing triangles whole, which is how "leave this area joined" works. Shells the cut never touched (eyes, inner voids) are merged into the piece that contains them.

**Real sculpts are messy, so the cap has several safety layers** (each found on real figure files, each with a test):
- `prepareMesh` drops loose specks (`removeSpecks`: shells under 0.001 mm³ and 0.5 mm, such as a triangle stored back to back with itself).
- `buildSection` moves the plane, by a few microns at most, to the middle of the widest gap among nearby vertices, so no section points crowd together beyond float32 precision.
- `buildRegions` nests by direction, not just depth. An opposite-running loop inside an outline is a hole. A same-running one is an overlapping inner solid (`nested`: its own cap, an obstacle for keys, never keyed). A lone backwards loop is a void speck (`inverted`: capped facing the other way, never shown or keyed).
- `untangledRing` snips microscopic self-crossing folds out of the outline before earcut. Microscopic holes skip earcut entirely.
- `fixTJunctions`, `splitThroughPoints` and `patchCap` then make the cap meet every ring edge exactly. `patchCap` orients by topology, because the leftovers are often zero-width slivers.
- `cutMesh` checks that every part is closed and, if not, retries a hundredth of a millimetre or so either side (`cutOnce`). If every retry fails it throws a plain-language error rather than export an open part.

Before merging any change to sectioning, capping or keys, run `node tools/sculpt_check.js <model files>` on real sculpts as well as the tests (`MIN_WALL=1.2 CURVED=1` adds the printability rules and curved cuts along every region line). Never commit model files; they are usually someone else's work. `tests/fixtures/sculpt-outlines.json` holds just a few 2D cut outlines that once failed.

Key outlines come from `keyProfile(shape, r, d, angle, res)`. A socket is the peg outline grown by the clearance `d` (never scaled), and the vertex count depends only on `shape` and `res`, so tapered top and bottom rings pair up. **Every key shape must be star-shaped around its centre**: the cap fans and the wall orientation in `cutMesh` and `makePin` rely on it, and `core.test.js` checks it. Peg taper is a percentage (`cfg.taper`, 0 to 100, where the old `true` means 20); the tip never shrinks below 2% of the width so it stays a real outline. A matching socket grows by `spec.cs = c·√(1+slope²)` so the gap holds at right angles to the sloping wall. Use `spec.cs`, not `spec.c`, for anything socket-sized. Each key may carry its own settings in `key.o` (any of `KEY_OVERRIDES`: shape, diameter, length, clearance, taper, taperSocket, turn, align); the key type and peg side stay global. Merge them with `keyCfg(cfg, key)` and size anything for that key from `keyGeometrySpec(keyCfg(...))`. `evaluateKeys` checks a custom key at its own depths via `depthFor`, which sections them once and caches them on the analysis. Keep `key.o` when moving or flipping keys. By default keys are sized to fit each area (`cfg.sizeMode: 'auto'`): `autoFitKeys` tries `sizeLadder(cfg)` from the Largest setting down to the Smallest (pegs 1.2× as long as wide, dowel pins 2.5×, magnets from standard disc sizes), keeps each key to at most half the area's width so walls stay sturdy, and stores the chosen size in `key.a`, which `keyCfg` applies under `key.o`. `PRINTERS` holds the resin and filament presets (smallest key, gap, wall) that the model panel's Printer choice applies. The Largest key (`cfg.diameter`, the top of the ladder) follows the model's size (`fitKeySizeToModel`: 3.5% of the longest side, 5 to 15 mm, as kits of that size use) when a model is opened or scaled, until it is set by hand (`cfg.sizeByHand`): on a figure scaled to 300 mm a 5 mm peg was a dot. `KEY_SIZES` goes up to 15. `autoPlaceKeys` searches a grid, then, for any area where nothing fit, searches finer around its nearest misses (ranked by `slack`, how far a spot is from passing the check that stopped it), because thick walls or long shapes can leave a valid strip narrower than the grid. It returns the areas still without a key in `keys.empty`, with the reason, and the interface names them. Fit checks for non-round shapes use `footprintClear`, which follows the real outline. `splitThroughPoints` repairs cap edges that earcut runs straight past ring points, which happens when straight socket sides line up.

## Plugs

The fifth joint type (`cfg.type: 'plug'`), from the owner's own technique and professional kits: the cut face itself, pulled in from the edge by the wall, stands out from one piece into a matching pocket in the other, one per area. `planPlugs(an, cfg, skip)` works on flat (`analyzePlane`) and curved (`analyzeLoop`) analyses alike and returns, per listed area, `{ ok, reason, x, y, base, top, mouth, floor, depth, side }`: four anticlockwise rings with the same number of points (the plug's base and top, the pocket's mouth and floor) and the pocket's side (as for pegs, from `pegSide`).
- **Shape** (`plugShape`): the area rasterised on a fine grid, its distance from the edge (`distanceField`, an exact Felzenszwalb transform), kept where it's at least `inset` in, then rounded (the core grown back by `round`, at least the wall and 1 mm) so narrow necks and sharp corners drop out, the biggest piece traced (`contourLoops`, marching squares) and evened out (`evenRing`). Areas with a hole through them get no plug.
- **Rings**: the top is the base moved in by depth × tan(`plugSlope`, 5° by default) and the pocket is the plug grown by the gap held square to the slope, both by `offsetRing`; every ring is checked for crossings. A crossing outline is rounded twice as much first, and where the top ring folds over at a concave corner the plug is made shallower (×0.7 a step, down to 1 mm) before it is refused as irregular: a goblin's shoulder at 12° was refused outright for this.
- **Depth**: as deep as fits up to half the plug's narrower width (2 to 10 mm), or `plugDepth` when `plugDepthMode` is `set`, always capped by what the other piece can hold (checked along lines through the model: solid past the pocket's floor plus a floor, and round its walls). On rounded parts the other piece thins near the edge, so `planPlugs` also tries the plug pulled further in (1.5 to 6 walls) and keeps the deepest, up to the depth wanted.
- **Building**: `cutMesh(..., { plugs })` and `cutAlongLoop(..., { plugs })`. On flat cuts the plug's piece gets a hole at the base ring, the pocket's piece one at the mouth, each with walls facing along their own edges and a flat end from `endCap`, so any outline works. `endCap` orients the whole end at once from the outline's direction, never triangle by triangle: earcut leaves slivers where points line up, and far from the origin on a tilted cut a sliver's own normal can point the wrong way (the tree-trunk outline in `plugOutlines` caught this). On curved cuts `curvedLoopCap` treats keys and plugs alike as four outlines on the face that follows the line. Plugs set the pull direction like keys. **On curved cuts, "Pegs on" / "Plug on" means the piece being split off ("This piece") or "Other piece"**, not the halves of a flat cut: the app maps the choice per line through `curvedSide(pref, into2)` (side 1's material lies at -into2·n; 'below' names side 1) and passes `pegSide` per loop in `opts.perLoop[i]`, which `cutAlongLoops` folds into each line's `c.cfg`. Before this a plug on a shoulder stood on the body with its pocket in the arm, which read as "the other piece is too thin".

## Repair

`repairMesh(P, I)` makes a tangled export cuttable and reports what it did, in up to three passes (filling a hole can expose the next flaw): `{ duplicates, untangled, pinched, flipped, slivers, filled, skipped, report }`. Each pass: faces stored twice go (a face and its mirror twin are a zero-thickness fin, so both go); an edge with three or more faces, or two running the same way, has its faces paired by which side their material lies on (sweeping round the edge, a face's material is behind its normal) and its vertices split so each pair is its own surface (two parts welded along a seam become two shells); every vertex whose faces form more than one fan is split too (a pinch, which the hole filler can't close); each connected surface is walked so faces agree with their neighbours, and a closed one facing in is turned out; open slivers under 0.5 mm go; then `fillHoles`. `edgeTable` groups half-edges by their smaller vertex in typed arrays, so the faces on an edge are a short scan; the whole repair of a 400k-triangle part takes a few seconds. Stitching coincident boundary vertices was tried and dropped: it rejoined what untangling had separated. Models it can't close (the guenve pair: 1,000 open edges, 16 shells) are a job for Blender or Meshmixer, and the app says so with the count. In the app, **Repair surface** in the model panel runs it on every part, and a model that opens with gaps or tangles is repaired as it opens (`setModel` calls `repairSurface` with a lead sentence, and clears the history so the repair isn't an undo step): the owner's Goblin Liz has open edges, and every region pick on it was refused with "fill holes first" until it was repaired by hand.

## Cuts that print and go together

The owner's two rules: no cut may leave a piece too thin to print, and no cut may make pieces that can't be put together. Both are enforced in `core.js`, so the app, tests and `sculpt_check` all obey them.
- **Too thin.** `thinAreas(an, t)` casts lines along the plane's normal through each area (`rayGrid` and `solidRuns`, cached while the plane only slides; crossings count in or out by which way the surface faces, so overlapping shells such as eyes don't read as gaps) and measures the piece on each side. An area is too thin on a side when every sample is thinner than `t`, or when the thin samples at least `t` in from the outline cover 40% of the area (the thin band along a slanted cut's edge is normal and ignored). `cutMesh(..., { minThickness })` refuses listed areas with `thinMessage` (code `thin`) and quietly leaves thin unlisted specks joined. The app passes `minWall()`: the Wall setting, capped at the printer's wall. It shows the warning in the footer with **Leave it joined**, tags the area "too thin", and holds back Cut. Curved cuts check the two pieces where they meet with `jointThickness`.
- **Cut anyway.** The owner asked to be able to force cuts. `opts.force` on `cutMesh`, `cutAlongLoop(s)` and `splitRegion` turns the `thin` and `locked` refusals into `result.warnings` (`[{ code, message }]`); listed thin areas are then cut, only unlisted specks stay joined; `crack` and unsealed results still throw. In the app, a thin or hooked refusal on a region pick re-runs the pick with `force` and offers **Split it off anyway** / **Cut along it anyway** under the warning; the flat cut's footer and the held-back toast offer **Cut anyway** (`doCut(true)`), and a locked refusal's toast does too. A forced cut says so in its toast.
- **Only a crack.** If joined areas hold both faces of a cut area in one piece, `cutOnce` throws (code `crack`).
- **Hooked or caged.** `lockedPairs` / `slidesApart` compare the pieces column by column along the pull direction: each pair must be able to slide `pullDistance` apart (past the longest key, at least 3 mm) straight along the keys, or, with no keys, at a slant up to 40° or from one piece's middle to the other's. Clashes shallower than 0.05 mm or narrower than three columns are slivers and are ignored, and pieces that already overlap (an inner solid) print as one. On flat cuts only pairs that can lock are checked: one reaches across the cut through a joined area, or both are on the same side (a piece caged inside another). Code `locked`.
- **Lines cut together agree** (`orientLoops`): side 1 holds every line's forward edges, side 2 the rest, worked out from the pieces of surface the lines bound; `loopFrame` gives the same frame whichever way a line runs, so keys planned before a line is turned round stay where they were. The app orients hand-picked lines before planning keys.
- **Curved cut faces.** `straightLoop` moves a line off two sides of a triangle onto the third, so zig-zags along mesh edges don't fold the cap into teeth; `analyzeLoop` and `cutAlongLoop` both use it, so keys and cut agree. The cap is flat (earcut) unless it would repeat a surface edge, the line crosses itself flattened, or it doesn't seal; then it is fanned from `fanCentre`, a point the line can be seen from all round when there is one.
- **Smooth cut faces.** A cap drawn only between the line's own points is a few big facets, so a bumpy line gives a faceted face (the owner's complaint on a neck cut). `gridCap(rings, xyOf, H, step, addVertex, xyMap, wantCCW)` draws it as a regular grid instead: grid points at least three-quarters of a `step` in from every ring (the line and any key or plug outlines) get the face's height from `capHeight`, the cells with all four corners in are two triangles each, the grid's outline is traced into loops, and the band between each ring and the grid is earcut with the flat-cut safeguards (`fixTJunctions`, `splitThroughPoints`, `patchCap`). `capStep` is 1.5× the line's median edge, never finer than about 4,000 cells. It returns null for shapes too small or awkward for a grid, and the caller falls back to the plain cap (flat, or fanned where the flat cap clashed). The grid is tried even where the flat cap would be fanned, since its band often avoids the surface edge the flat cap doubled. The clash check (`surf`) covers the surface edges on both sides of the line, with side 2's copies mapped back to their original ids: a cap chord that doubled an edge on side 2 alone once slipped through and made a part with a four-face edge. `cutAlongLoops` retries without grids, then with fans, if a part isn't sealed. Both pieces share the grid points exactly (`addVertex` makes a pair, `copy`/`other` link them). Midpoint subdivision of the earcut triangles was tried first and dropped: skinny earcut triangles stay skinny when split, so the face still crinkled, and it added ten times the triangles. Keep an eye on the cost: on a 140k-triangle miniature, splitting off a region adds a few thousand triangles and takes about a second.

## Sunk cut faces

The owner's "impossibly thin walls": a shallow region split off along its outline is a lens that thins to nothing at the rim, because the cap membrane hugs the surface there. Smoothing the region labels (morphological opening, tried at 0.8 to 2 mm) did not help and was dropped; what helps is **sinking the face**. `sunkRing(P, I, F, ring, xy, h, into2, want, wall)` pushes each line point straight along the frame normal into side 2 (`intoSide2`: the piece that doesn't hold the line's forward edges; for lines picked by hand `orientLoops` makes side 1 the smaller side, so the recess goes into the bigger piece) as far as there is solid to hold it with a wall to spare, checked with `solidRuns` (nothing where only air lies beyond the line, as under an overhang or along a ball's widest part), smooths the depths along the line (moving minimum, then mean, over a wall's length) and checks the face over the sunk ring the same way (10th percentile of room at least three-quarters of a wall, halving the depth otherwise). Walls that followed the other piece's surface normal were tried and dropped: on a bumpy line the pushed points crossed each other. `cutAlongLoops` with `opts.sink` builds, per loop, a sunk ring of new vertices, straight walls from the line down to it (quads `(b, a, la), (b, la, lb)` on side 1, mirrored on side 2), and the cap (grid or keyed, `curvedLoopCap(..., sunk)`) over the sunk ring; `analyzeLoop` with `cfg.sink` uses the sunk ring as the base loop, so keys, plugs and checks all sit on the sunk face. Recesses at both ends of a piece trap it (a sleeve sunk into the shoulder and the cuff), so when the lock check fails the longest line alone is sunk, then none, before the refusal stands (`sinkPlans`, `c.use('sunk' | 'plain')`). The result carries `sinks` per loop. In the app, **Sink face** (mm, 0 off, default 1) sits in the regions panel beside **Draw a cut line**; the pick says how deep the face is sunk, or that there's no room.

## Painted selections

What Meshmixer and ZBrush do, and what the owner asked for ("similar ability to make cuts as in meshmixer, or zbrush"): paint faces with a brush, split them off, cap the holes. `brushTriangles(P, I, start, centre, radius)` floods from the triangle under the brush across the surface (`triangleAdjacency`, cached per index array, with centroids) keeping triangles within the radius, so a dab on a hand doesn't paint its far side; `growSelection` / `shrinkSelection` work in millimetres (Dijkstra from the selection's edge over centroid distances; shrink grows the complement); `tidySelection` opens then closes by `r`, dropping tongues and filling notches narrower than 2r. `selectionSeg` turns the selection into a two-group labelling (1 painted) through `bordersFromGroups`, and `splitRegions(P, I, seg, [1], opts)` cuts it like a region: a painted area always has a closed outline, so it always separates (unlike a single clicked line), and keys, plugs, sinking, force and shift-click apply. In the app, **Paint an area** in the regions panel (`setPainting`) makes drags on the chosen part paint (`paintAt` raycasts the part's mesh for the point and `faceIndex`; `paintDab`), Shift-drag or the **Erase** toggle erase, the brush size is in mm, **Grow**, **Shrink**, **Tidy edge** and **Clear** edit the selection (`paintEdit`), and letting go of the pointer picks the painted area (`pickPainted`, `state.regions.last.painted` for replays). Painted triangles show blue over the region colours (`renderPaint`, from `v.regionColors` kept by `applyRegions`). Drawn-line dots are fixed-size `THREE.Points` now, after the owner found the spheres obstructed the view. The brush shows as a circle its own size lying on the face under the pointer (`brushRing`, `moveBrushRing`, `hoverBrush`); it starts at 3% of the part's diagonal until set by hand (`state.paint.sized`), because a 3 mm brush on a figure scaled to 254 mm painted nothing visible; the selection resets if the part under the brush changes (scaled, or another chosen); and **Show faces** (flat shading, `state.flat`, `setFlat`, the view-tools button `#flatBtn`) is on by default (the owner's request) and turned on by painting if off. **Painting never waits on a cut**: a dab writes only the faces it touched and sends only their span to the graphics card (`renderPaint(only)` with `updateRange`), raycasts are throttled to one per 20 ms, and letting go shows the outline alone (`previewPainted`: `selectionSeg` + `groupLoops`, tens of milliseconds, `pick.preview`); **Split off painted area** (`splitPainted`) then runs the full pick with keys, plug, sinking and checks and cuts at once if it passes, or shows the refusal with **Split it off anyway**. Before this every stroke end ran the whole cut (a second or more) and every mouse move rewrote and re-uploaded all the model's colours. **Isolate** (modelsplitter's Mask tool; `paint-isolate` / `paint-show`, `state.paint.iso`) keeps only the painted triangles on screen and under the pointer: `applyIsolation` puts an index of those triangles on the part's otherwise unindexed geometry, so three.js draws and raycasts just them, `v.isoMap` maps a hit's face index back to the triangle, and the brush never paints outside the isolated set; the cut still uses the whole model. Stopping painting, or the part changing under the brush, shows the whole model again. The brush has two modes (`state.paint.mode`): **Surface** (`brushTriangles`, a flood that stops at the edge of a layer) and **Sphere** (`sphereTriangles`, every face within reach, layers behind included, for clothing over a body); **Fill** (`state.paint.fill`) makes a dab paint the whole surface region under the brush; **Snap to borders** (`snapSelectionToRegions`) paints whole every region at least half painted by area and clears the rest; `[` and `]` size the brush (`setBrushSize`).

## Lines drawn by hand

The owner's "manual painting capability for cuts". `drawnLoop(P, I, points)` takes clicked points (part coordinates), snaps each to its nearest vertex (`nearestVertex`) and joins them in order, and back to the first, by `surfacePath`: Dijkstra over the vertex graph (`vertexAdjacency`, cached per index array) with edges charged a little extra for straying from the straight line between the two points, so the way runs where a hand would draw it. Where a vertex comes round again the detour is dropped, so the loop is simple. The result is a loop like `borderLoops` gives (`verts`, `closed`, `length`, `drawn: true`), so `cutAlongLoop`, `analyzeLoop`, keys, plugs, force and shift-click all work on it unchanged. In the app, **Draw a cut line** in the regions panel (`setDrawing`) turns clicks on the chosen part into points (`addDrawPoint`, dots and the path so far in blue from `renderDraw`); Enter, the **Close the line** button or a click by the first point closes it (`closeDrawing`) and picks it like any line; Backspace or Ctrl+Z takes a point back (Ctrl+Shift+Z puts it back), Esc stops drawing. The drawn loops are kept in `state.regions.last.drawn` (an array: drawing again adds a line to the lines already picked, so several drawn lines cut together; Esc clears the pick for a fresh start) so the pick replays when the key settings change. Curved key markers draw through the model (`depthTest: false`), as the plug marker did, so pegs inside a limb can be seen.

## Shapes

modelsplitter's Shapes tool, the first of its three model-editing tools (Shapes, Boolean, Sculpt), in the **Edit the model** row under the cut tools. `shapeMesh({ kind, w, d, h, inner, edge, edgeSize, segments })` builds a closed solid centred on the origin: a cube as a box (`boxMesh`), chamfered by 20 planes through `polytopeMesh` / `hullMesh` (the convex solid inside a set of outward planes, built face by face: each plane's face is a big square clipped by every other plane, corners shared by plane triple and welded where more planes meet at one point; the chamfer is held to half the smallest side so chamfers from opposite edges never meet) or rounded as the box grown by a ball (`roundedBoxMesh`: a cube-shaped grid of directions with an odd count a side, each direction mapped to the box's support point plus the radius; the flat faces and the rounded edges are spanned by the grid's own quads, each split along its shorter diagonal so the surface stays convex, as the booleans need); a ball, a tube, a cone (`d` is the top's diameter, 0 for a point) and a ring (`inner` the hole) as lathes (`latheMesh`) of a profile, with `shapedCorners` replacing the profile's convex corners by a chamfer or an arc. Every shape is checked closed in `core.test.js`. `clipMesh(P, I, { o, n }, { shift })` is the exact plane clip the chamfered cube and the booleans use: both sides come back closed, with caps that mirror each other triangle for triangle (one triangulation, given to the below side facing +n and to the above side facing -n), crossing points computed from the lexicographically smaller end of each edge and split quads taking a position-ordered diagonal, so two copies of a face cut by the same plane split alike; each side is welded by position (float32 can fold a crossing point onto a vertex) and a triangle welding doubles counts once. In the app a shape is a part like any other (`part.shape` holds its settings and `shapePositions` builds its positions, turned X then Y then Z as three.js's XYZ Euler and then moved, through `rotXYZ`, the same matrix three.js builds), so cutting, export and the parts list need nothing new; `addShape` sizes one to 30% of the model and puts it at its middle, the panel (`shapePanelHTML`) has the kind, the sizes, the edges, the handles' mode (Move, Turn, Size), the place and the turn, Centre on model and Stand on the ground, and the gizmo (`attachGizmo` with the shape's mesh centred on its middle, `centreShapeView`; `bakeShapeDrag` folds a drag into `part.shape` and rebuilds the part, one undo step per drag) moves, turns or sizes it. Delete removes a chosen shape; Esc lets it go. Projects save a shape's geometry but not its settings, so a reopened shape is a plain part. Shape meshes are float64 (`weld(..., true)` keeps float64), so a boolean sees them exactly.

## Booleans

modelsplitter's Boolean tool, in the **Edit the model** row: `booleanShape(P, I, shape, op)` joins a shape to a part (`union`), takes it out (`difference`) or keeps only the overlap (`intersect`), for a shape as the app places it (turned X, Y, Z then moved). **The tool is convex, or several convex cells that share faces**: a cube, ball, tube or cone is one closed mesh with flat faces (`facePlanesOf` groups neighbouring triangles whose normals agree within a thousandth of a radian into one face, so a turned shape's float32 quads stay one plane); a ring is its sectors (`ringSectors`: one list of planes, the radial ones and the flat top and bottom shared, each sector a list of `{ g, sign }`), built here with `hullMesh`, and a plane two cells share with opposite signs is inside the tool and gets no cap. `booleanWith(P, I, tool, op)` with `tool = { positions, indices }` or `{ planes, cells }`:
- **The tool is moved, whole, by a few microns** (`toolShift`: along a few directions, each vertex within tolerance of a plane forbids a short run of shifts, and the middle of the widest gap wins), so no part vertex sits on a plane. Moving planes one by one (`nudgePlanes`, dropped) broke a ball's pole, where many faces meet, into a cluster of slivers.
- **Every part triangle near the tool is clipped by each cell's planes** (`clipByCell`, Sutherland–Hodgman on a polygon whose edges carry a label: a part edge or a plane), giving inside pieces (one per cell) and outside pieces. **Every seam point has one name**: a crossing of part edge `e` with plane `i` is `e{e}p{i}`, shared by the triangles on both sides; a corner where the tool's edge `i∩j` passes through triangle `t` is `c{i}-{j}t{t}`, and `seamNear` reuses a corner already made on the same line by another pair of planes (a ring's radial face meets two wall facets along one edge; a tool edge through a part edge gives both triangles the corner). A point within `eps0` (scale × 1e-9) of a plane is **on** it (`on` list, `registerOn` puts it on every tool edge it lies on). The second pass (`paramsOn`, `sewn`) splits every piece edge at the seam points on it, including those the triangle across a part edge made (`onEdge`), and whole triangles beside a cut one get those points too, so nothing has to be sewn afterwards; pieces are fanned from their centroid.
- **The tool's facets are arranged**: each facet's outline (its corners plus the seam corners on its edges, in order) and the seam chains of the inside pieces on it (`chains`, per facet) form a planar graph, walked with the leftmost turn into loops; anticlockwise loops are regions, clockwise ones holes (the loop that runs the outline backwards, and a region's own twin, are not holes), earcut with the flat-cut safeguards. **A region's side of the part comes from the seam direction**: the part's inside piece lies on the left of each seam edge, so a region whose boundary runs against a seam is inside the part; regions with no seam on their boundary take their side from their neighbours across tool edges without seam points (union-find over outline edge keys), and only a tool nowhere near a seam is tested with a line through the model (`insideTester`, parity, the sample nudged off any edge).
- **Assembly**: intersect = inside pieces + caps inside the part; difference = outside pieces + those caps flipped; union = outside pieces + caps outside the part. Edges shorter than scale × 1e-6 are collapsed where the collapse keeps the mesh a manifold (`collapseShortEdges`), so a float32 copy never has two vertices in one place (the next boolean, or a cut, tripped on them), then a weld of exact doubles only, `edgeReport`, and a plain-language error if not sealed ("Move the shape a little and try again"). A shape that misses the part refuses the overlap, one that swallows it refuses the difference; a shape wholly inside a part makes a void.
- **Tested** on the knot with every shape, random placements and turns (a stress script ran 765 placements without a failure), chains of booleans, and a cut through the result; `core.test.js` checks volumes add up (overlap + difference = the part, union = part + shape − overlap). A 250k-triangle model takes about a second (a ring three). Sequential sectors with overlapping, staggered planes were tried for rings and dropped: each step's seams landed microns from the next step's planes.

In the app, **Boolean** (`setTool('boolean')`, `state.bool = { shapeId, op }`) works on the chosen part with one of the shape parts (`enterBoolean` takes a chosen shape as the shape and the first other part as the part, or the chosen part and the last shape added); the panel (`booleanPanelHTML`) has the shape list, the part (click another part in the view to change it, or a shape to make it the shape), and Add / Cut out / Keep overlap, with the Shapes buttons when there is no shape yet; the foot button (`BOOL_LABELS`) or Enter runs `doBoolean`, which replaces the part with the result, removes the shape, clears its region cache, goes back to the Plane tool and says what it did, as one undo step, or shows the core's message on failure.

## Sculpt

modelsplitter's Sculpt tool, the third of its model-editing tools, in the **Edit the model** row. `sculptDab(P, I, { centre, radius, strength, mode, reverse, start, mask })` moves vertices in place on `P`: the vertices it can reach across the surface from the triangle `start` under the brush and within `radius` (a flood over `vertexAdjacency`, so a thin part's far side is never caught), each weighted by the falloff `(1 − (d/r)²)²`. **Smooth** eases each vertex towards the middle of its neighbours (from the positions before the dab), **inflate** moves along the vertex normal (the sum of the face normals round it, `vertexTriangles`, a CSR cache per index array) by `strength × radius × 5%` at the centre, or in with `reverse`, and **flatten** presses towards the plane through the brush area's weighted middle with the mean of its normals. With a `mask` (a painted selection, by triangle) only vertices of painted triangles move. It returns the vertices moved and the triangles round them, and `refreshCreased(P, I, tris, pos, nor, creaseDeg)` rewrites just those triangles in the display arrays `creasedArrays` made (positions and crease-split corner normals), which `core.test.js` checks against a full rebuild. The surface's connections never change, so a sealed part stays sealed (a strong stroke can still fold it through itself, as in any sculpting tool). In the app, **Sculpt** (`state.sculpt = { mode, size, sized, strength, mask, useMask }`, `sculptPanelHTML`: the brush, its size in mm, which starts at 4% of the part's diagonal until set by hand, and the strength) makes a drag on the chosen part a stroke: `sculptAt` raycasts the part, dabs on a copy of its positions kept in `stroke`, and refreshes the touched triangles' span on the graphics card (`updateRange`); `endSculpt` commits the part with the new positions as one undo step, drops its region, line and suggestion caches and rebuilds its view. Shift reverses Inflate; `[` and `]` size the brush (`setBrushSize` routes to `setSculptSize`); the brush ring is shared with the paint brush (`brushSize()`). Entering Sculpt from a painted area keeps the paint as a mask (`enterSculpt`), shown as **Keep to the painted area (N faces)**.

## Reduce detail

modelsplitter's Reduce for cutting: `reduceMesh(P, I, { target, tolerance })` is quadric edge collapse (Garland and Heckbert) in plain JavaScript. Every vertex carries the sum of its faces' plane quadrics; a binary heap holds the edges by cost (each collapses onto whichever of its two ends or their midpoint costs least), entries go stale by vertex version numbers; a collapse must keep the mesh a closed manifold (the edge has exactly two triangles, and its ends share exactly two neighbours: the link condition) and turn no triangle over (normals before and after within about 78°); it stops at `target` (a fraction or a count of triangles) or when the next collapse costs more than `tolerance`² (the cost is a squared distance to the faces' planes, so the surface stays within about the tolerance). A vertex's triangle list can hold triangles killed by an earlier collapse, and they have to be skipped everywhere (they made the flip check reject almost everything, which stalled the reduction at half the mesh). Peter Akimoto, 117k triangles, goes to 51k within 0.02 mm in a second, closed, volume within 0.05%. In the app, **Reduce detail** in the model panel (Light 0.02, Balanced 0.05, Strong 0.1 mm; `reduceModel`) reduces every part as one undo step, clears the region and line caches, and says how many triangles went. Exports use what was cut, so a reduced model prints reduced; the toast says Ctrl+Z puts the detail back.

## Engraved joint numbers

modelsplitter's joint numbers (roadmap item 12): **Number the joints** in the key settings (`cfg.numberJoints`) engraves the same number on both faces of each cut, so a big kit pairs up. `jointMarks(sec, ri, keys, cfg, number, { mirror, depth })` lays the number out as seven-segment strokes at the clearest spot of the area away from its keys (`regionSamples`, scored by clearance minus the label's half-diagonal and each key's reach), as big as fits from 3 mm strokes down to 1.5 mm, each stroke nudged by a hair of its own (two pockets whose edges line up exactly left the cap's triangulation with collinear points it couldn't always sew up: digits 0, 4, 8 and 9 came out open); with `mirror` a second set mirrored about the label's centre goes on the other face (`side: +1`), so each reads the right way round. `markKeys` turns strokes into key-like objects (`mark: true`, shape `bar`: a stroke 2r long and 0.56r thick, a both-sides socket 0.6 mm deep with no clearance) and the cut routines carry them beside the keys: `cutMesh(..., { marks })` (`cutOnce` skips a mark on the side it isn't for; `marksUsed` in the result) and `cutAlongLoops` with `perLoop[i].marks` (`c.marks`, `curvedLoopCap` treats a mark as a socket on both pieces, never a peg or a pin; on a curved cut both faces share one face, so the number on one piece reads mirrored). ## Cut suggestions

The owner's verdict on the first version was "terrible" (pins on the base's edge, on thumbs, across the torso; nothing at a neck or shoulder), so suggestions are now judged by what they free. `neckSweep` slices the part along `sweepDirections` (13 fixed plus the principal axes), follows each area from slice to slice, and flags two kinds of spot: a **narrow point** (an area under 60% of the wider ones on both sides) and a **join** (an area meeting one 2.5× bigger: the chain starts or ends beside a much bigger area, or drops or jumps within itself, as a shoulder, a hip or a head whose neck is hidden by hair; the small side must hold its size for another slice, or a flat base's edge counts). `refineNecks` merges these, tilts each plane until it sits square across the neck, and then measures each with `freedBy`: the surface on the normal's side is flooded from the area's outline without crossing the plane, through every other area of the plane, which gives the piece's volume (its triangles summed with the caps, which lie in the plane through the origin and add nothing) and the areas the piece is bounded by (`areas`, the ones that must be cut with it: an arm's shoulder cut must also cut the strap over it). A spot is dropped when it frees under 1% of the model (a thumb), or when an extra area is over 60% of the main one (both legs at once: a slice, not a joint). The score is √(freed share, full at 8%) × √((1 − pinch) × q), with q = 1 / (1 + ratio / 1.5) and ratio the cut area over freed^⅔ (a ball cut through its middle is 1.2, a limb at its joint well under 1), times a vote factor. Spots near each other that free nearly the same piece (a forearm at two places) are one. `creaseEdges` and `creasePlanes` find planes where inward creases cover at least a quarter of the cut outline, and drop any that only trims a sliver (checked with `freedBy(..., true)`, the whole plane). `regionCuts` suggests surface regions to split off along their outline (an arm, a head, a backpack): each region whose outline closes is measured without cutting (its triangles plus a cap per outline fanned from that outline's centre; the outlines' flattened area as the cut area) and scored the same way; its `point` is the region's innermost triangle (most steps from a border), used for the pin and to pick the region as a click would. `separateShells` finds solids that don't touch (inner shells stay with their host; each carries `tris`, the triangles of the original it holds, so a clicked triangle maps to its piece). **The Suggest tool shows no cut plane until a flat cut is placed** (`state.suggestPlane`, set by `placeFlatCut` for a suggestion, a spot or a line across the view, cleared on entering the tool or choosing a part; `planeShown` reads it): the owner found a plane with its area chips under "Split into separate pieces" confusing. **Split into separate pieces** is a preview first (`startShellPick`, `state.shellPick = { partId, chosen }`): each loose piece in a colour of its own (`shellColor`, `renderShellPreview` over the colour attribute, the unticked ones greyed), a tick per piece in the list (`shellPickHTML`), a click on a piece in the view ticks or unticks it (`shellAtFace`, `toggleShell`), and **Separate N pieces** (`splitShells(chosen)`) makes the ticked ones parts of their own and leaves the rest together as one part, shown apart (explode at least 35%). The app runs the search a direction at a time between frames, caches results per part, and letters the suggestions (areas are numbered); each says what it frees. A flat suggestion sets `state.cut.focus` to its `areas`, and the next analysis leaves every other area joined; a region suggestion turns regions on (with the fold the search used) and picks the region through `pickCutLine`, so keys, plug, sinking and the checks follow, and the pins stay on the model while regions show. A flat cut at a limb's root can't free it when the limb touches the body (an arm against the chest: the flood takes the body), which is what the region suggestions are for.

**Cut at a spot** (the owner's click-to-cut-here): `cutHere(P, I, point, scale)` tries planes through the clicked point with normals in and around the surface's tangent plane there (15° apart in it, 30° apart on rings 30° out of it), measures each by the area whose outline the point lies on and `freedBy` (with `at`, a point well inside the area from `regionSamples`), keeps the lowest cut area for the piece freed (area over freed^⅔; the smallest area alone would be a sliver shaved off the surface, the biggest piece a slice through the body), skipping any that frees under 0.5% or needs a second area over 40% of the first (both legs), then tilts it, still through the point, in 12°, 6°, 3° and 1.5° steps. About a second on a 160k-triangle figure. In the app, **Cut at a spot** in the suggestions panel (`setHere`, `state.here.on`, crosshair cursor, Esc stops) arms the next click on a part: `cutHereAt` runs it under the busy indicator, adds the result to the part's suggestions as the active one (`addHereSuggestion`, kind `here`, one at a time) and places the plane through `placeFlatCut` with its `areas` as the focus. Clicking a neck gives the neck; clicking an arm that rests against the body gives whatever flat cut through that spot frees a piece, which may be small, so the hint says to click a limb, a neck or an accessory.

## Form: the parts of a figure by thickness

The owner's "intelligence to detect form and parts": limbs, a head, a torso, a weapon are told apart by how thick the solid is under the surface (the shape diameter of Shapira, Shamir and Cohen-Or), not by how the surface turns. `meshGrid(P, I, n)` is a cell grid of the triangles and `castInward(grid, P, I, o, d, maxT)` walks it (3D DDA, Möller–Trumbore) to the first face whose back the ray meets: the far wall seen from inside. `shapeDiameter(P, I, { cone, rays, smooth })` sends, from each vertex nudged inward, the inward normal's ray and 12 rays on a 45° cone round it, keeps the rays that see a wall within 2.5× the straight ray's distance (at a corner or an edge half the cone leaves through a neighbouring face at once; the ray lengths are taken as they are, as the shape diameter is defined, so a tube reads about its diameter and a ball less), takes the median, and smooths it three passes in log space over `vertexAdjacency`. `segmentForm(P, I, { ratio, minFrac, smoothness, sdf })` takes each triangle's mean log thickness, clusters the thicknesses into levels (area-weighted k-means from six seeds, levels closer than `ratio` (1.35, the panel's **Tell apart at** 35%) merged), labels each triangle by its own fit plus its neighbours' labels (a few passes of iterated conditional modes: across a concave crease a neighbour counts a seventh as much), makes each connected run of one level a region, melts regions under `minFrac` (2%) of the area into the neighbour they share most border with, and returns what `segmentSurface` returns plus `levels` and `sdf`: so picks, cut lines, suggestions (`regionCuts`) and splits all follow unchanged. A head and a torso of like thickness still part at the thin neck between them, because the neck is its own level and a region is one connected run. `subdivideMesh(P, I, { maxEdge })` splits every edge longer than `maxEdge` with the triangles beside it (one, two or three split edges give two, three or four triangles; neighbours share the midpoints, so the mesh stays sealed), because the thickness is read per triangle and long thin triangles blur it; the test figure (a rounded torso, a neck, a head, two arms and two legs joined by booleans) is subdivided to 3 mm before its parts are checked (each of the six in a region of its own, 80% or more of it, 80% or more pure). The knot, the same thickness all along, is one region. About 0.5 s on the 33k-triangle knot. In the app, **Find: Parts | Sections** (Parts is this; first Form | Folds, then Parts | Folds, then Thickness | Creases) at the top of the regions panel (`state.regions.by`, `regionsKey`, the Form slider **Tell apart at**, `state.regions.ratio`); the thickness is kept per part in `sdfCache` (the slow half) and forgotten when the part is sculpted or reduced, so moving the slider re-clusters at once.

## Parts: form and creases together

The owner's "detect obvious separate parts like arms, legs, tools in hand, feet, bases, hats or clothing separation like shirt and pant borders, backpacks, bags". `segmentParts(P, I, { ratio, fold, angle, strength, minFrac, sdf })`, which the app uses for **Find: Parts** with **Detail** (Big, Balanced, Fine: `state.regions.detail`, `DETAIL` sets `ratio`, `strength` and `minFrac`; it replaced the "Tell apart at" slider the owner couldn't make sense of) (`state.regions.by === 'form'`): the thickness runs (`segmentForm`, specks kept at 0.4%) and the crease regions (`segmentSurface` with the fold) are overlaid, slivers under 0.3% melt, and then neighbouring regions are merged, the weakest border first, until every border is at least `strength` (0.5) strong. A border's strength is the largest of: its **concave** share (a valley at least `fold` deep: a collar, an armpit, a hat's brim, a hem); a **step** in mean log thickness against the ratio (an arm against a torso, a sword against a hand), counted in full only with a valley or a narrowing to back it (`support = 0.35 + 1.5·concave + 1.5·neck`, since across a flat plate the reading drifts from thick by a wall to thin at the rim, and a hat's brim came out as four rings); and a **neck** (the border short against the smaller region's girth, 2√(π·area)). Steps and necks along a convex ridge (a box's edge, a plate's rim) don't count, since the thickness reading jumps there by itself. What is left under `minFrac` (2%) joins the neighbour it is least separated from. Tested on the boolean figure (six parts each held and pure at 80%), the knot (one part) and a hat on a head (the crown its own part). **The thickness is sampled** (`shapeDiameter` `samples`, 16,000 by default): rays go out from one vertex per cell of a grid sized to the sample count, the rest take their nearest sampled neighbour's value over the surface before the smoothing; it reads within 6% of casting from every vertex and a 94k-triangle figure went from 3.5 s to 0.7 s. **The work runs in a Web Worker** (`coreTask(fn, args)`, a worker built from the page's own core script, `#kmCoreScript`, via a Blob URL, with a main-thread fallback): `startRegions` sets `state.regions.loading` (so `planeShown()` is false and the plane, gizmo and bar step aside at once), shows the busy sign, awaits `prepareRegions(p)` (which fills `regionCache` and `sdfCache`), then turns the regions on. `regionsFor` still works synchronously from the cache, or computes on the main thread when nothing prepared it (the suggestions, the debug hooks).

## Picks in the background

The owner's 352k-triangle figure froze for up to half a minute on every region pick: the trial cut ran on the main thread, and a refused one ran three times. `planPick(P, I, req)` in core does everything a pick needs (orienting hand-picked lines, `analyzeLoop` per line with `curvedSideOf`, keys or plugs, joint marks, and the cut with its fallbacks) and returns plain data: `perLoop`, `frames`, `draw` (per line, each key's `{ k, angle, lv }` and each plug's `{ base, top, z0, tip }`, from which `curvedKeyMarkers` / `curvedPlugMarkers` draw without an analysis, which carries functions), `noKeys` and `dropped` as codes (the app words them: `noKeysText`, `droppedText`), `result`, `error`, `forced`. **The cut is tried forced first**: a forced cut builds the very same pieces and turns the thin and locked refusals into `warnings`, so the warnings tell what an unforced cut would refuse; without them it is the result, with a locked one and joints it is tried once more without the joints (unless the region is held at both ends, `wedged`, which joints can't fix), otherwise the forced result stands. The unforced sequence remains as the fallback when the forced run throws. `pickLoops` draws the outline at once in grey with "Checking the cut…" (`pick.pending`, the foot button waits, Enter says to wait, `cutAlongPick` refuses), runs `planPick` through `coreTask` (the worker posts `KMCore.plainData(result)`: functions dropped, typed arrays kept), and a newer pick supersedes it (`pickRun`). `pickSettled()` waits for the latest pick, following replacements; the debug hooks that read a pick await it, and `autoSplit` and `splitPainted` await theirs. The lock check caches each piece's `rayGrid` per direction (`pieceRayGrid`, a WeakMap on the index array) and samples 30,000 columns, not 60,000 (the finer grid had found a hairline clash on the figure that 30,000 and 20,000 both pass). A refused pick on the figure went from 26 s to about 5 s, with the view drawing at 60 frames a second throughout.

## A stroke that wraps a cut round a part

ModelSplitter's Line, as the owner asked ("draw a line that automatically creates a cut after the line analyzes the surface and wraps around parts smoothly and intelligently"). In the Draw tool a left-drag is a stroke (a click still adds a point; Alt-drag orbits): `strokeCut` takes the plane through the stroke's ends and the eye, the point `o` where the stroke crosses the chosen part nearest its middle (raycast at 25 spots along it), and runs `strokeLoop(P, I, { o, n, scale, maxTilt })` in the worker. ## Speed of finding parts and picking (1.66)

The owner found part and region selection "still very slow". **Finding the parts** was three times faster for the same result (99.4 to 100% of triangles in the same region on six reference figures; the cat 7.7 s → 2.6 s): `trianglePairs(I)` is the neighbouring triangles across each edge, built once per index array with `PairMap` and kept in a WeakMap (the part finders and `bordersFromGroups` had each built it with a JS Map of a million keys); `segmentForm` clusters the thicknesses on a 2,048-bin histogram (each bin at its triangles' own area-weighted mean, seeds by triangle count as before); and `segmentParts`'s merge loop keeps each region's area and thickness as running totals (`join`) and rescans only the edges that were borders after the overlay (`cand`). **The worker keeps meshes**: `coreTask` sends a mesh once under a key from its index array (`meshKeyOf`, a WeakMap; a new array is a new mesh), the worker keeps the last four, and resends on `mesh-missing`, so core's caches keyed on the index array live between calls. **A pick can be cut while it is checked**: the foot button stays live while `pick.pending`, a press (or Enter) sets `pick.cutWhenReady` and the cut follows the check if it passes unforced; a refusal or a forced result is only shown. **The lock check asks the same pieces about a keyless pull**: when pieces with keys lock, `checkPieces` also tests them at a slant without keys (`keyless` on the warning), and `planPick` builds the pieces again without joints only when that would free them (a neck pick on the cat went from 17 to about 10 s). **The stroke's line shows while dragging**: `#acrossLine` is an SVG element, whose `hidden` property never touched the attribute, so the line (and the line of Cut across the view) had never shown; `showAcrossLine` sets and removes the attribute.

## Fill gaps, pieces pushed into another, one exploded view (1.67)

- **Fill gaps** (the owner's "auto fill gaps between selected parts to complete the selection"): `fillSelectionGaps(P, I, sel, { gap })` closes the selection (grown by `gap`, then shrunk, so channels narrower than 2·gap between picked pieces fill; nothing picked is ever dropped), then fills every unpicked patch that borders the selection and isn't the biggest such patch (the outside) and is smaller than the selection, and keeps only what joins up with the picked triangles. Patches that don't border the selection at all (another loose piece) are left alone: the backpack figure's second piece had been filled whole. In the app, **Fill gaps up to N mm** sits under every pick (`fillPickGaps`, in the worker, default 1.2% of the part's diagonal, `state.fillGap`): the pick's area (`pickSelection`) is completed and picked again as a painted area (`pick.selection` keeps it, so `regionTint` tints it when painting is off, and a painted pick's `[1]` is never read as the part's region 1); the paint tools have **Fill gaps** too, at half the brush.

## Loose pieces in a pick, smooth cut lines, scaled meshes in the worker (1.69)

- **Loose pieces inside a pick go with it.** `splitRegions` sets aside every `shellComponents` piece wholly inside the picked regions (no line runs through it), cuts the rest (`opts.noLoose` on the inner call; each line's joints follow it by matching vertex positions, since the order of the lines can change), and merges them into the regions' piece (`r.loose` counts them). ## Smoother region cuts, plugs on miniatures, unpinched regions, Parts | Sections (1.70)

From the owner's Aysil ("can't have jagged and unsmoothed cuts, or keys; parts need to slide together smoothly") and eleven more reference figures (Aysil, Brandon Jaspers, Brim, the boy with the large spoon, the Elephant, guenve, Ghuun, the Faceless Doll, Darrin Flash Williams, trace, Apparatus of Kwalish).

## Sliced cuts, the after-cut print check, kept picks (1.71)

From the owner's Aysil arm ("must be smoother and not jagged or have fine, tiny points and angles"; "the application should be able to slice topology and not just cut along existing topology vertexes").
- **Region and painted picks are sliced** (`sliceRegionPick(P, I, seg, groups)`, used by `pickMesh` for any pick with `regions` and `seg` when `req.smooth`, before the old re-routing, which stays as the fallback): the pick becomes a field over the vertices (the distance along the surface to its outline, Dijkstra within a band of 4 × `scale`, + inside, − outside), smoothed by neighbour averaging (about 1.5 (scale / median edge)² passes) and moved by a level so the side kept holds as much surface as the pick did (smoothing shrinks a convex patch: a dab on a coarse ball lost a quarter and came out too thin). The cut follows the zero level: each crossed edge gets one vertex, 12% to 88% along it, shared by both triangles, and each crossed triangle becomes three, so the surface stays sealed and keeps its volume. `scale` is 1/40 of the shortest outline, at least three median edges and at most 1/15 of it; islands under 2% of the smaller side change sides (loose shells wholly in or out are left); the slice is dropped if the area kept moves by more than a quarter. The sliced mesh is a new mesh: `planJoints` returns the lines' points as `paths` (the app draws them, and keeps `pick.loops` as the lines on the part itself); `req.sliced` stops a second slice, `req.noSlice` turns it off. A failing pick is offered only forced (`out.printCheck`, `printMessage`), like any thin refusal. Flat cuts keep `thinAreas`.
- **Kept picks**: changing Find or Detail keeps a region or painted pick as the triangles it covers (`keepPick` / `restorePick`, as a painted selection), so the new regions add to it.
- **Small bumps**: Shift-click on a region much bigger than the pick (the body, or four times the pick) adds only the patch between creases under the click (`fineRegionsFor`: `segmentSurface` at fold 12°, angle 50°, `minFrac` 0.0002, cached per index array) when it is under a tenth of that region and smaller than the pick (a pauldron's spike in the chest); a second Shift-click takes it out (`addToSelectionPick`).
- **Holes fill themselves**: letting go of the brush fills every unpainted patch the paint closes round (`fillSelectionGaps` with `gap: 0`), and clicked regions that close round other regions take them in (`enclosedRegions`).
- **Keys while painting**: `previewPainted` runs `planJoints` in the worker and draws the keys or plug on the painted outline; the cut still waits for Split off painted area.
- **The Sphere brush shows as a ball**: `brushBall`, a see-through sphere of the brush's size, a child of `brushRing`, visible while painting in Sphere mode; Surface keeps the ring.
- **Brush size sliders** (`#brushSlider` beside Brush, `#sculptSlider` beside Size): a log scale from 0.2 mm to two fifths of the part's size (`sliderOf`, `sizeOfSlider`), live while dragged, kept in step with the box and [ ] (`syncBrushSlider`).
- **Show: Both | This piece | Other piece** under every pick (`state.pickShow`, `applyPickShow`): the hidden side's triangles leave the view's index, as Isolate does.

## Strokes sliced along their plane, flat cuts in Split into parts (1.76)

From the owner's forearm stroke ("slice drawn lines is not slicing the topology as expected… this is a feature model splitter has and it works well"), and "split into parts is virtually worthless".
- **A stroke is sliced along its plane** (`slicePlaneLoops`, used by `sliceDrawnLoops` when every loop carries a `plane`, which `strokeLoop` now returns with the tilted ring's `{ o, n }`): every vertex takes its signed distance from the plane (never clamped to a band: clamped, a long edge's crossing point moved to its middle, which put the line a millimetre off the plane on Aysil), `sliceByField` slices through every ring of the plane (it now returns `parent`, each new triangle's original), and the pieces are joined back across every crossing but the stroke's own ring, the chain of crossed triangles flooded from the line's vertices across shared edges (one ring, however close another runs: a finger beside a finger, a fold of cloth), blocking only edges inside a chain triangle with both ends new. Side 1 is the pieces the ring separates that hold more of the side the line bounds, else every one but the biggest (the edge-walked line can cut corners, so its side is a poor guide); loose shells stay side 0. No island pass and no area check for strokes: the ring is the plane's own. - **Hard surfaces are labelled by panel** (`hardSurface`): a flat panel of two or more coplanar triangles takes one label from the area-weighted mean of its own triangles, and lone triangles average only with lone neighbours. - **A piece held at both ends may come out along a joint** (`checkPieces`): the lock check of a pair tries the other lines' normals between the same pieces and their sum as well, `keyless` is asked for wedged pairs too, and `planPick` builds again without the joints when that frees them. **A clash counts from 0.05 mm or a quarter of a percent of the pair's size** (`slidesApart`): a tenth of a millimetre on a figure scaled to 150 mm had refused every split.

The toast counts the flat cuts.
- A pick's volumes read in mm³ under a cubic centimetre (`fmtVol`), not "0.0 cm³".

## Parts rebuilt: 1.70's grouping, props carved out (1.79)

- **The made props are fixed from the start** (`hardSurface` → `propLabels(P, I, made, A, pairs, total, minProp)`: connected runs of made surface at least `minProp` = min(`minFrac` / 4, 0.3%) of the surface and at most 35% of it; a run parts at a concave seam of 60° or more only where that leaves two pieces each at least `minProp`, a block standing on a box, never where a groove merely crosses a face). - **A small part attached by a narrow contact stays a part** (the melt's keep rule, replacing 1.72's): a region at least `keepArea` (`minFrac` / 4) whose borders are all at least `keepStrong` and whose border length to **sculpted** neighbours is under 0.7 of its girth (2√(π·area)). A hand lying on a book touches the book all along its underside, which doesn't count, and the skirt along a sliver (5 mm of a 21 mm girth); a panel of robe between two folds is bordered along its whole outline and melts. Within a melt pass a region whose neighbour already changed waits for the next pass (`touched`), so what is judged is what the stats say.
- **`hardSurface` is by triangle shape**: the share of triangles over three rings that are thin (a corner under 12°) and lie in a flat patch of three or more coplanar triangles (`thinScore` > 0.35), or a large flat face (at least 0.2% of the surface, two or more coplanar triangles) scored hard by the gentle-edge rule (a CAD box exported as two triangles a face isn't thin). ## Split into parts

## Surface regions

`segmentSurface` joins neighbouring triangles whose normals differ by less than `angle`, like ZBrush polygroups by normals, then melts regions under `minFrac` of the area (0.3%) into the neighbour they share the longest border with. With `fold` set (the app uses `fold: 15, angle: 60`), a concave turn (a valley: cloth meeting skin, a collar, a belt's edge, a shoe top) splits at that gentler angle while a convex one (a ridge) still needs `angle`: on organic sculpts the parts meet in valleys and ridges are mostly detail, so this gives arms, legs, hands, heads and garments as their own regions where splitting at any turn merged them. It returns `groupOf` per triangle, region areas, and `borders` (pairs of triangles and their shared edge). `regionBorderLines` turns the borders into line segments lifted a hair off the surface. In the app, the Regions tool shows the chosen part's regions by colour alone since 1.67 (no outlines; `regionBorderCurves` is kept for tests and tools; before: smooth, soft border curves, the mesh's zigzag border edges chained and rounded by two passes of Chaikin corner cutting, in a deep shade of the part's own colour at 90% (light ink vanished on a pale part in dark mode), because the owner found the solid black outline ugly; only the chosen part, or one already worked out, is outlined, since finding every part of a model of many pieces at once stalled it; with the part's own colour kept; the owner found coloured regions noisy), with the fold slider in a small panel; the cut preview steps aside while regions show, and cutting turns them off. `regionTint` lays the picked regions in a strong amber (85% over the part colour) and dims the rest of the part to 78% while anything is picked, so a pick stands out on a pale figure (the owner couldn't see the old 55% tint on a cream sculpt), and the region under the pointer (`hoverRegion` → `setHoverRegion`, `state.regions.hover`, a raycast every 40 ms) a pale yellow over the part colour in the colour attribute (`v.regionColors` is the base the paint goes over; lifting the hovered region a shade towards white was lost on a pale part), and `#regionHover` in the regions panel says how much of the surface is under the pointer while nothing is picked. **A region with no outline is a whole loose piece** (or the whole part): `pickCutLine` sends it to `pickLoose`, which matches the regions to `separateShells` pieces by their `tris` and makes a pick with `loose` (the piece indices) and no loops, shown as "a loose piece, no cut or keys needed" with **Separate this piece** (`cutAlongPick` → `splitShells`); the owner's KANDEN, a kit already in pieces, was refused with "covers the whole surface" on every region. **The arrow and the rings go with the plane** (`attachGizmo` attaches the gizmo only while `planeShown()`), and the **Select** tool (`state.tool === 'select'`, first in the cut tool row) chooses a part by clicking it, or lets it go on empty space, with no plane, bar, gizmo or cut button, and the Joints folded.

## Curved cuts along a border

**Splitting off a region** is what ZBrush and Meshmixer do with a selected group, and the owner's expectation. `splitRegion(P, I, seg, g, opts)` cuts along the region's whole outline, all its loops at once (`regionLoops`; an arm has a shoulder loop and a cuff loop), through `cutAlongLoops(P, I, loops, opts)`: side 1 is the triangles holding the loops' own directed edges (the region, since `regionOutlines` runs with the region's winding), flooded with every loop's edges blocked; side 2 is the rest, split into pieces with `separateShells`. Loops are cut together, never one at a time, because where the surface loops back on itself (an arm whose hand rests on the hip) no single loop separates it. Keys or a plug go on each loop from `opts.perLoop[i]`; the thickness and lock checks run per loop on the two pieces it separates, and a region held at more than one end by one piece (a shin between a thigh and a shoe standing on the same base) is refused with a message to split a neighbour first. `cutAlongLoop` is a one-loop wrapper. In the app, a click within 1.5% of the part's size from a border line cuts along that line; a click anywhere else on the part picks the region under it (`regionAtPoint`) and offers **Split off this region**. **Shift-click adds to the pick**: more lines (cut along them all at once through `cutAlongLoops`, which then separates both sides into their shells; `opts.what: 'lines'` words the "doesn't free a piece" message) or more regions (`splitRegions` / `groupLoops`: the union's outline, with the borders between the chosen regions dropped, so a face, hair and collar come off as one head; regions that don't touch come off as separate pieces). Lines add to lines and regions to regions; shift-clicking something already picked takes it out again. The clicks are kept in `state.regions.last.clicks` and replayed (`replayPick`) when the key settings change.

`cutLines` lists the lines a curved cut can follow: borders between two regions (`borderLoops`) and whole region outlines (`regionOutlines`), which can run past several neighbours. `borderLoopNear` picks the shortest closed line through the border edge nearest a clicked point. `cutAlongLoop` splits the surface along that line's existing edges: it floods the triangles on each side (refusing a line that doesn't split the part), gives side 2 its own copy of the line's vertices, and caps both sides with the same triangulation facing opposite ways. The cap is the line projected on its best-fit (Newell) plane and triangulated with the flat-cut safeguards; if any cap edge would repeat a surface edge (a border zig-zagging along triangle edges) or the line folds over when flattened, it fans from a centre point instead. A line round a dip gives a piece of negative volume and is refused with its own message. Untouched shells join the piece around them. **Hollowed models are a known gap**: a curved cut only cuts the outer surface, so an inner void shell that the cap passes through stays whole and is merged into one piece, which then reads as a dip (negative volume) or hides a void that spans both pieces. Flat cuts slice inner shells like any other. Keys on a curved cut sit on a face that follows the line however much it bends (`curvedLoopCap`): the face's height off the best-fit plane is blended from the line's heights by mean value coordinates (`capHeight`, and `capHeightGrid` for fast lookups), triangulated once with a hole per key's socket outline and shared by both pieces so they meet exactly. The peg's piece adds a thin ring of face across the fit gap, then the peg. Keys are straight, along the plane's normal: a peg's length counts from the highest point of its base on the socket's side, so it always reaches its full length into the other piece, and each socket is measured the same way from its own side (`keyLevels`). `analyzeLoop` gives an analysis shaped like `analyzePlane`'s, so `autoFitKeys`, `autoPlaceKeys` and `evaluateKeys` work unchanged on it; `keyScore` sends curved analyses to `curvedKeyCheck`, which checks along lines through the model (`solidRuns`): no more than 45° of slope under the key, solid walls to the socket floor, a solid floor, and, for pegs, solid at least a wall's depth under the peg in its own piece, so it's anchored. A line that crosses itself when flattened (beyond microscopic folds, which are snipped as on flat cuts) is cut without keys. While surface regions show, the hidden cut plane ignores the pointer: drags orbit. A click on a part that isn't the selected one selects it (`regionClick`), so its key settings show on the right; a click on the selected part picks a region or line on it. Turning regions on with a single part selects it. A change to the key settings re-runs the last pick (`state.regions.last`), so the pegs or plug on the picked region follow the settings.

## Made objects and the surface they own (1.80)

The owner's book, again: "clearly there is still an issue, specifically with the book". Driving the built page with the real three.js and a real mouse click (Paint with Fill, from below, at 1000%) showed it: a click on the book's underside took the whole front panel of the skirt (3,498 triangles) in Parts, and a strip of it in Sections. **The cause**: the book's bottom face is a recessed page block behind the cover lips, made (thin fans) but only 5 mm², so under the prop size, and it runs on into the skirt with no crease at all (the cloth is sculpted flush under it), so the crease pass put it in the skirt's region and the melt left it there. The book itself was five separate made runs (the covers' panels, the straps, the clasps) a millimetre or two apart, with even-triangled fillets and channels between them.
- **`convexHull3(pts)`**: quickhull with outward planes. A point within 1e-4 of the extent of a face counts as inside (flat panels hold hundreds of coplanar points), and a face is visible from a point strictly beyond its plane: with the tolerance in the visibility test, a coplanar neighbour stayed while the face beside it went, and the cone over the leftover edge folded the hull (every facet had points outside it).
- **`propObjects(P, I, prop, nProps, made, N, C, A, pairs, opts)`**, called from `propLabels` after the made runs: the runs are grouped into objects (Dijkstra over centroid distances from every run at once; two runs join when the way between them is under a quarter of the larger run's diagonal, crossing a concave crease only from made to made, and only when together they are still one rigid shape: the area-weighted rise of their surface under the hull of the union under 6% of its diagonal, so a cuff a millimetre from a book, whose union hull bridges over the hand, never joins). Each object's hull is its outline in space, and it claims the surface round it that lies on the hull: reached over the surface, the plane holding the whole hull behind it within `supMade` (30%) or `supPlain` (2%) of the diagonal, the inward line entering the hull within `deepMade` (30%) or `deepPlain` (2%); made surface and flat panels (three or more triangles within a degree of one plane: the book's side between the straps, even-triangled) on the lenient terms across any edge, curved sculpted surface on the strict terms, never across a concave crease of 30° or more and only within `band` (5% of the diagonal) of the object, measured over the surface, so a hand lying on the cover, whose pads meet it too gently for a crease, stays out. An object claims at most its own area, all or nothing (a flange's thin rim reaching both faces of the flange claims none). The sculpted runs it then encloses join it if under a fifth of it (was half: a hand between the book and the cuff). Props are kept from `total × min(minFrac / 4, 0.002)` (was 0.003: the cuff ring was just under).
- **Sections** (`segmentSurface` with `fold`) runs `propLabels` on its hard labels and counts the objects' surface as hard, so the border lands at the page block's edge; `seg.hard` in Parts carries the objects' surface too, so the pick's slice pins the seam round it.
- **With Fill on, `previewPainted` adds nothing** (no gap closing, no hole filling): the hand, shut in between the book's region and the cuff, had filled as a hole of the book's region. Fill gaps under the pick still works.
- Checked on the built page with the real renderer (`KeymasterDebug.setView`, `screenPointOf`, `paintedTriangles`, `pickTriangles`, `meshOf` are for that): the page block's pick is the book's bottom strips and clasps, the cover's the whole book (11,535 triangles, no robe), the hand's the hand (9,610), the skirt's the skirt; Rhinehardt 26 → 22 parts at Balanced, Aysil 23 → 20, Brim 30 → 22, Hero 25 → 22, Bills 33. Tested: a made plank fused into a sculpted body with its recessed front flush with the body's front, as built, turned and scaled, in Parts at every Detail, in Sections, with Fill's closing and the sliced pick.
- Known: the segmentation differs a little with the model's scale (float32 positions ×10 flip a few made labels: the book region 11,535 triangles at 100%, 8,577 at 1000%, the hand the same); 1.79 did the same. Tried and dropped: hull per made run (the book's runs are panels, the page block lies far from any of them); the 2D hull of a panel's rim (the page block has a rim on one side); grouping runs by surface distance alone (a cuff joined the book over the hand); claims without a band (the hand's pads came in at the tangent contact).

## A made object's pieces, wherever they lie; an outline that can't fail (1.81)

- **`ownObjectPieces(P, I, groupOf, made, prop, A, C, N, pairs)`**, the last step of `segmentParts`: every made triangle in a region that isn't an object's is tested against each made object's convex outline (2.5% of the object's diagonal). It belongs to the object when it lies deep inside the outline (a recessed page block), or on it and not facing into it (a fingertip, the cuff resting on the cover, and the fan of thin robe triangles round the book all face into it). Connected runs of passing triangles of at least 0.01% of the surface move to the region holding most of that object. Testing whole pieces was tried first and failed: the lip's piece also held the robe fan, which faces the other way.

## Regions by shape, not size; a made object's strips (1.82)

The owner: "none of the logic should be based on actual size of the model, but the topology and understanding of what the model is… only the key development should be based on the actual real world size." - **Each part keeps the surface its regions are found on** (`part.analysis = { P, f }`, `analysisOf(p)`): the positions as opened, and the factor from them to the part's own. `transformAll(fn, label, factor, even)` keeps it through an even scaling (`scaleAll`, `setScalePct`, linked sizes) and `dropToGround` through a move; a turn, a stretch on one axis, sculpting, repair and reduction clear it, so the next analysis starts from the part. `prepareRegions`, `regionsFor` and `fineRegionsFor` segment `analysisOf(p).P` and scale `seg.areas` back by f² (`scaledSeg`); everything else in a seg is per triangle. `KeymasterDebug.regionLabels()` gives the chosen part's labels, and `ui_test.py` checks ×10 leaves them identical. ## Limbs: kept whole, ended flat at the joint; knife edges and Thinnest piece (1.83)

The owner, after 1.82: the arm should end at the shoulder at Balanced; cutting it off at Fine left "super thin sharp edges" (the capelet's rim as knife flaps on the body, a spike on top of the arm); "add an adjustment for the thinnest a part can be after cutting".
- **Tubes stay parts** (`tubeLike(s, short)` / `tubeAxis`, from area-weighted sums `[A, Σx, Σxxᵀ, Σnnᵀ]`: the normals' spread has almost nothing along one axis (≤ 0.13) and plenty across it (≥ 0.3), and, unless `short`, the surface is at least 1.8× longer than wide along that same axis). A sleeve or a leg passes; a cape (normals point up as much as round), a belt (longest across its own axis) or a coat panel doesn't. In `segmentParts`'s last melt (`melt(..., keep)`), a tube region at least `keepArea` is never melted for being small, and nothing joins or is joined by a kept tube unless the two together are still a tube (`tubes.tubeWith`, `tubes.joined` keep the sums), so a leg's pieces still join each other and a sleeve never goes into the cape. On Rhinehardt at Balanced both sleeves are now their own parts (they had melted into the capelet and the coat's back, at 1.3% and 1.5% of the surface); Hero and Brim gain their arms; Aysil, Bills and the Elephant are unchanged at Balanced.
- **A limb ends in a flat cut** (`limbEndPick(P, I, seg, groups)`, run by `pickMesh` for region picks before the slice, `req.limbEnds: false` turns it off): an outline of the pick whose picked surface within 2.5 girth-radii is a tube stub (`tubeAxis(..., true)`), with the rest of the part at least 1.5× the pick, is replaced by the ring of a plane square to the tube's axis. The plane starts at the outline's mean height along the axis and moves into the limb in quarter-radius steps (at most a radius and a half), taking the first ring that is the tube's own (0.4 to 1.6 of its girth, containing the axis) and meets the surface squarely (mean |surface normal · plane normal| at most 0.3, else the squarest). The surface is sliced along that ring alone (`sliceByField`; the chain of crossed triangles seeded from the ring's points; the plane's other rings, through a cape, stay joined), and the pick becomes what is reached from the picked triangles on the limb's side without crossing the ring or the pick's other outlines. `sliceRegionPick(..., { pin })` then smooths the other outlines with the ring's points pinned. When every outline is a flat end the face is not sunk (`sink: 0`): sunk, a flat end left a thin collar round the recess. On Rhinehardt the full raised arm (sleeve, cuff, hand and cross) comes off just under the capelet with a flat round end and a peg, the capelet whole on the body.
- **Knife edges** (`knifeEdges(Pin, parts, t)`): each original triangle of a piece within 4 t of the cut's rim casts inward (`castInward`, sampled to 12,000); under half a t behind it is blade, counted for the nearest rim point; a rim point (averaged with its two rim neighbours) whose blade is wider than t is a knife point, and a run of them along at least 4 t of rim is a knife edge. `planPick` runs it after `cutPrintCheck` (`req.noKnifeCheck` turns it off) and offers such a pick only forced, with the length. Positions are compared as float32 on both sides. About 0.3 s a pick on Rhinehardt. Tested: a box cut at 8° to a face has one, at 45° none.
- **Thinnest piece** (`#minPiece` in the regions panel beside Sink face, `cfg.minPiece`, 0 = follow the printer): `minWall()` returns it when set, so the flat cut's thin check, the after-cut print check, the knife check, inlays and flat splits all use it; choosing a printer puts it back to the printer's wall (`syncMinPiece`).

## One tool for picking; Parts and Sections (1.84)

The owner: "the regions and paint tools can be combined into a single tool since painting with fill effectively works like regions. Parts should select limb, hardware, armor, books, objects, large separate parts that aren't body parts, etc. Sections should be more sectional... smaller pieces of defined parts, where a section is where a border or otherwise detectable delineation in a single part is."
- **Regions and Paint are one tool.** The tool row no longer has Paint; the Regions panel starts with **Pick by: Click | Brush** (`#pickClickBtn` with `data-tool="regions"`, `#paintBtn` with `data-tool="paint"`, both in `#regionsPanel`). `setTool('paint')` still turns the brush on, but `state.tool` stays `regions` (`syncTool`, `go()`), `renderToolGrid` presses Click or Brush from `state.paint.on`, and `TOOL_NAMES.paint` reads Regions. `ui_test.py` turns the brush on through `brush_on(pg)`.

The app finds the parts first (cached under `partsKey(p)`, shared with Parts) and the sections from them (`regionsKey` for Sections now carries the Detail too). On Rhinehardt 73 sections, none crossing a part (the plain crease sections had 14 that did, a sleeve band into the cape and so on); about 0.9 s on top of the parts. Tested on the boolean figure: no section holds two parts' triangles.

## Repository standards

Keymaster follows the shared TechSavage1989 standard in `docs/REPOSITORY_STANDARDS.md` (the same file in every app repository), which every AI tool reads through `AGENTS.md`. In short: the README keeps the standard centered header and section order and is updated with any user-visible change; screenshots are real captures with fictional data in `docs/images/` (`hero.png` + kebab-case names) and are recaptured in the same pull request when a UI change makes them stale; nothing built or private is committed except `index.html`, which must be rebuilt; branches are short-lived (`feat/`, `fix/`, `docs/`, `chore/`) and deleted after merging. Where this file differs from the standard (for example, bumping `VERSION` in every pull request, including documentation-only ones), this file wins.
