# Keymaster 0.2.0 alpha 2 - plane interaction stability (unreleased candidate)

## Crash fix
- The previous widget listened to continuous VTK mouse events, rebuilt plane geometry, and modified widget representation during the native callback. This could crash the process when clicking or dragging the plane.
- The widget now reports only end-of-drag poses. Its callback captures the pose without touching VTK actors or native widget state; the Qt event loop applies the result afterward.
- Programmatic coordinate/slider changes synchronize the widget only outside VTK mouse callbacks.
- Stale callbacks from disabled or replaced widgets are ignored, and pending pose updates are canceled on closing or loading a new model.

## More direct on-plane controls
- The plane's center sphere and outline/frame are the Move handles. The normal arrow is the Rotate handle.
- Choose Move + rotate, Move only, or Rotate only to control which attached handles are active.
- Turn off Show interactive plane handles to avoid the widget entirely and continue using numeric controls on unsupported graphics drivers.
- The model is not resliced continuously during a drag; intersection and cut previews update when interaction ends.

## Testing and remaining limitations
- Qt UI regression tests simulate native callback lifetimes and ensure no actor/widget operations occur before the native event returns.
- Windows CI runs an offscreen VTK widget lifecycle smoke in a separate Python process. This does not reproduce hardware-specific mouse events or guarantee the absence of graphics-driver crashes.
- No changes to the Manifold3D selective cutting engine, key geometry, source mesh, or non-destructive export.
- This draft does not authorize automatic release publication. Publication requires a fresh explicit approval, verified checks, tag and checksum.
